**Status:** PROPOSED (owner design decisions of 2026-07-28 recorded here; build order awaits owner go)

## 0. Thesis

v1 is an agent tracker with approvals. v2 (004) makes it a durable work ledger with standing agents and evidence. **v2.1 makes it a substrate users program**: the default experience stays exactly 004's supervised ledger, and a stream's charter can additionally summon a Cursor-style agent swarm — frontier planning, cheap parallel workers, machine-verified results, budget-bounded autonomy — without a new product surface. Reference model and economics: Cursor's agent-swarm post (hybrid frontier-planner + cheap-worker ran ~8× cheaper at equal quality, workers carrying 69–90% of tokens). We have no users yet; shipping this is an edge, not a risk to an installed base.

### The ten principles (distilled 2026-07-28; every §2/§3 change traces to one)

1. **Machines get config, agents get prose.** Deterministic behavior (launch, width, budgets) is enforced from typed values; prose governs judgment. (Owner, round 2; consistent with 004 §3.4 rule 3.)
2. **No attestation-only evidence.** Every evidence kind must be mechanically checkable: re-runnable, externally confirmable, content-addressed, or identity-signed. (Owner: "deterministic test outcome — but only that, nothing else.")
3. **Fixed strata, unbounded lateral growth, promotion over nesting.** Depth is planner recursion; we represent it as tasks-spawn-tasks plus child-stream promotion, never a recursive tree. (Owner, round 4; Cursor's five failure modes are deep-tree diseases.)
4. **A subtask is a fully-collapsed instruction.** No dependencies, no children, no planning — that constraint is what makes cheap-model execution safe.
5. **The backstop is a first-class scaling surface.** Recovery drains a dirty set; it never enumerates all tenants. (CF review A1.)
6. **Rails are identity- and diff-enforced, never approval-enforced.** This is why autonomy can exist: removing approval removes no safety rail. (004 §4 + review of what survives autonomy, §4 below.)
7. **Every fan-out and sweep declares a budget against a named platform limit.** (CF review; the ~167-tenant wall was an undeclared budget.)
8. **One identity namespace past the boundary.** (Settled 2026-07-28 — rooms and events unified on authority-internal org ids; Clerk claims are auth-only.)
9. **Doorbells carry cursors.** A contentless ping forces refetch-everything and makes loss undetectable. (CF review A5/B3.)
10. **Human comprehensibility is a product invariant.** Flat UI, legible Needs-you, receipts — even (especially) for autonomous streams.

### The v0 authorship rule (owner directive, 2026-07-28)

**WorkGraph has zero users. Everything shipped is authored as v0 — the first coherent version — never as a layer over prior versions.** Concretely:

- Code, comments, schema, UI copy, and user-facing docs are written as if the current design were always the design. No "previously", "legacy", "v1/v2", "replaces the old X", "renamed from Y" anywhere in shipped surfaces. When touching code that carries such comments, rewrite them as v0 as part of the change.
- **Delete, don't deprecate.** Unused states, fields, commands, and routes are removed, not marked legacy. No compat shims for behavior no one ever used.
- **Schema changes may be breaking.** There is no user data to migrate; drop-and-recreate beats migration scaffolding until there are users. (Dogfood data is disposable by declaration.)
- The plan docs (this file, 004, the review) are the **internal decision log** — the one place history lives. The product and its docs never reference them or their version vocabulary.
- The canonical external-facing description of the system is `docs/workgraph.md`, written v0-style.

This rule is a review gate alongside §4: a phase that ships version-archaeology language in code or user-facing docs fails review.

## 2. Amendments (each: what 004 says → the 2026-07-28 decision → the new rule → why it is safe)

### A1. Autonomous streams — amends 004 §3.6 and §7

- **004 says:** agent-proposed work always arrives Staged; "no agent can approve — not the master, not via MCP, not via any charter sentence." §7 lists "auto-run intake tiers" as permanently out.
- **Owner decision (2026-07-28):** "There should be autonomous mode — no human approval. Not enforced [on everyone]… primary use continues as-is, but experimenters opt in."
- **New rule:** a stream's envelope may declare `autonomy: supervised | autonomous` (default `supervised`, forever). In an autonomous stream, agent-created tasks are **born `pending`** — the born-state consult reads stream policy before the actor-type rule. The 004 invariant survives verbatim: **no agent ever approves anything** — in an autonomous stream there is simply nothing to approve, because the human pre-approved the *class* of work at charter time, deliberately, with hold-and-confirm on the flip itself.
- **Non-overridable carve-out:** work whose provenance traces to public/untrusted sources (004 guardrail 2, Phase 4 ceilings) **stays Staged even in autonomous streams**. Injection defense does not participate in autonomy. Budget exhaustion and `failure_halt` hold the stream and surface Needs-you exactly as today.
- **Why safe:** principle 6 — every rail that actually contains blast radius (draft PRs, owner-only public/merge/close, landing diff gate, protected-ref permission facts, loop-breakers, provenance ceilings, budget caps) is enforced by identity, diff inspection, or arithmetic — none by the approval step. The UI labels auto-admitted work as such (principle 10).

### A2. Subtasks: the execution stratum — extends 004 §3.1/§3.3

- **004 says:** Task is the unit of execution; one attempt = one fresh worker session. No stratum below.
- **Owner decision:** subtasks exist, and they "can't depend on anything — no further planning can happen, just executes."
- **New rule:** an optional `parent_task_id`, **one level only**. A subtask has no dependencies, no children, no admission planning, no proposal rights; it is created only by its parent task's run (or during planning) carrying a fully-collapsed explicit instruction; it reports up (evidence, findings, `call_master`) — it never plans. Completion rolls up: a parent cannot complete until children are terminal. Born-state follows stream policy like any agent-created record. 004's standing-agent table gains a row — note it describes a **work unit's seat**, not an agent class (the executing agent is whichever profile is assigned, per A11):

| Seat | Scope | Lifetime | Wakes on | Authority |
|---|---|---|---|---|
| **Subtask run** | one subtask | minutes | launched once | execute the instruction in the parent's placement context; record evidence; report findings up; `call_master`. The reduced surface binds ANY profile in this seat: no task creation, no proposals, no planning. |

- **Why this shape:** principle 4 — the no-planning constraint is the safety property that permits cheap models and wide fan-out (Cursor: "once a frontier planner has collapsed the ambiguity… less expensive models simply have to follow it"). A subtask that needs judgment is a task; the assigned agent's move is to escalate, not think.
- **Depth doctrine (owner, round 4):** no recursive *task* nesting, ever, in this plan. Recursion = tasks spawning tasks (lateral, in time) + **promotion to a child stream** when a subtree needs its own charter/master/context — child-stream mechanics are A13. Revisit only if dogfooding proves promotion clumsy.

### A3. Verifiable-only evidence — tightens 004 §3.5

- **004 says:** evidence is the spine; prose is a claim, evidence is a link; structural gates on landing.
- **Owner decision:** evidence kinds exist *only* to enable deterministic verification — "should be only that, nothing else."
- **New rule:** four verification mechanisms are admissible — **re-run** (a recorded command), **external reference** (a provider API can confirm: PR merged, package published), **content hash** (artifact), **identity signature** (owner confirmation). Kind disposition: `test_result` keep + wire actual re-run; `integration` keep + confirm the reference; `artifact` keep, hash required; `owner_confirmation` keep (already identity-hard); `review` demoted — valid only with an external review reference; `finding` reclassified as knowledge, never completion currency (it already isn't consulted by contracts). Evidence rows gain `verification_status: unverified | verified | failed` with verifier provenance; a completion contract may require `verified`, and autonomous-stream defaults do.
- **Why:** principle 2. This converts the one soft layer the 2026-07-28 review identified (agent-attested claims) into hard gates by *execution*, using the types as the hook — the very reason to keep types at all.

### A4. The charter compiler: derived typed envelope — interprets 004 §3.4, extends §4

- **004 says:** the charter replaces the typed configuration surface entirely; hard limits live in the envelope; a blank charter degrades to conservative defaults.
- **Owner north star:** "users build systems like this for themselves by using stream charter."
- **New rule:** the user-facing surface stays **prose only** (004 wins; no settings tree). At charter draft/edit time, the planner **compiles** the prose into the stream's typed envelope — new fields: `autonomy` (A1), `max_parallel`, `placement` (`shared | worktree | sandbox`, per-kind defaults), `agents` (the stream's available agent profiles + assignment defaults per work shape — A11), `budget` (tokens or currency per window), `verification` (required evidence kinds; review lenses on/off), plus the existing landing pattern set. The compiled values are shown diff-style at confirmation (this also answers 004's open question 2 — side-effectful charter lines get surfaced because they *become visible envelope values*), are versioned with the charter hash, and conservative defaults fill silence. Agents read prose for judgment; the drain/oracle/budgeter read only the envelope (principle 1). Charter sentences can never exceed the hard guardrails (004 §3.4 rule 3 unchanged).
- **Example:** *"Plan on the frontier model; execute 6-wide on the cheap tier in worktrees; verify everything by test; budget $50; autonomous within that; draft PR until I say."* — compiles to `{autonomy: autonomous, max_parallel: 6, placement: worktree, agents: {...profile assignments...}, budget: {...}, verification: {required: [test_result:verified]}}`.

### A5. Capture without execution — nuances 004 §3.6/Phase 0c; partially amends §7

- **004 says:** direct human asks just run (deleting v1's worst failure); "per-task manual starts" are permanently out.
- **Owner concern (round 1):** "if user-born are directly executed it's a problem" — a typed thought is not a launch order.
- **New rule:** creation carries intent. The default create remains **run** (004 stands — no mandatory start button returns). An optional **`draft` flag** at creation (and a bulk "arm" action) records a task without arming it; draft tasks are visibly inert and excluded from the oracle. This is a capture affordance, not a per-task start step — the distinction 004's exclusion was protecting.

### A6. Batched planning — reconciled via flow streams; no new config surface

- **Owner ask (round 1):** planning should be batchable/configurable (`auto | batched | manual`), not one LLM run per intake.
- **Resolution:** 004 §3.2 already restructures intake as a **flow stream's feed triaged by its master per its charter**. Batching is therefore charter prose on the flow stream ("triage in batches of ten," "only when I ask," "auto-promote obvious bugs"), compiled per A4 where it needs determinism (batch size, cadence). The current per-candidate `propose_admission` gains multi-source input as machinery, but no per-view policy enum ships — the owner's configurability lands in the charter, which is the whole thesis.

### A7. Master wake economy — extends 004 guardrail 4

- **Owner critique:** "why at daily schedule without any work — it's useless."
- **New rule:** schedule wakes are **dirty-gated**: a master's scheduled turn is skipped when no events landed since its last turn (wake coalescing already exists; this extends it to the schedule trigger). Cost note that motivated it: today's design burns one real agent session per open stream per day regardless of activity.
- Deferred, explicitly not in this plan: a master→running-attempt push channel (mid-flight steering). `call_master` remains the only inter-agent primitive (004 §3.3); within-stream coordination happens between attempts, via the master and stream notes.

### A8. Model tiering and budgets — new; the economics half

- Model tiers live inside **agent profiles** (A11); the envelope routes work shapes to profiles at different price points — the Cursor economics ($1,339 vs $10,565) applied per stream by assignment, not by hardcoded role types. Budgets: `llm_usage_events` already lands one row per model turn; add stream attribution, per-stream aggregation, and a drain-side check — budget exhausted ⇒ stream held + Needs-you (never silent overspend). Usage and spend become visible on the stream card for autonomous streams (principle 10).

### A10. Runs, not attempts: resume-first execution — amends 004 §3.3 ("one attempt = one fresh worker session")

- **004 says:** one attempt = one fresh worker session; retry mints a new attempt.
- **Owner decision (2026-07-28):** the dominant failure is transient (network, rate limit, sandbox eviction, token expiry) — that must **resume the same chat with its cached context**, not restart fresh. "Attempt" as a user concept is over-engineering: a task just links to a session plus execution config (harness/model); session-layer compaction/continuation handles longevity.
- **New rule:** the ledger keeps one **run record** per task execution — exactly the link the owner described: `{session_id, execution config, generation, started/finished, outcome}` — and retry semantics invert:
  - **Resume is the default.** Transient death (relay drop, limit, sandbox eviction) is an *in-run* event: re-place the workspace if needed (sandbox checkpoints, plan `2026-07-27-004`, are the substrate), reattach the session with its history (already durable in the authority), continue. The ledger records nothing but a parked interval; no new run.
  - **Fresh is deliberate.** A new run (fresh session, generation+1) happens only on explicit restart — wrong path, poisoned workspace, model/tier change — by human action or a charter-compiled policy (e.g. "escalate to the frontier tier after two verification failures").
  - **The state machine shrinks to crash-recovery breadcrumbs**: durable-intent → placing → running ⇄ parked → terminal. Intent/placing persist *only* because a crash between sandbox-provision and session-launch must be findable by the reaper (otherwise it is invisible leaked billing — the exact B1 failure class); parked replaces the attention-stall state.
- **What survives and why (mechanical, not conceptual):** (1) the **generation/lease epoch** on every runtime callback — a zombie sandbox that returns from a network partition and posts "completed" after a fresh run started MUST be rejected by fencing, or the resurrected run overwrites the live one; (2) **per-run attribution** — evidence, receipts, and spend hang off the run record, or budgets and "which run claimed the fake green test" become unanswerable; (3) **a running-flag per lane** for the derived scheduler.
- **User vocabulary is unchanged by construction:** 004 already ruled attempts machinery, never user-facing; the UI shows a task running/parked/stopped and its session history. The v0 authorship rule applies — the shipped code says "run", not "attempt", with no renamed-from archaeology.

### A9. Stream notes ≙ Field Guide

- 004 already has the master maintaining a stream notes doc. Amendment: notes are **auto-injected into every attempt's context under a line budget** (Cursor's "Field Guide" pattern), with provenance fencing per guardrail 2 intact. This is the shared-context mechanism that lets parallel agents avoid re-deciding settled questions ("no two subtrees decide the same question" — the master enforces it, the notes carry it).

### A11. Agent profiles — replaces role vocabulary (owner directive, 2026-07-28)

- **Owner decision:** avoid planner/worker/sub-worker vocabulary everywhere. The forward concept is the **agent profile**: a *named* agent identity — `{name, harness, model, skills[], mcp_tools[], memory (portable), capability_brief}`. The master receives each available profile's brief and **assigns profiles to tasks and subtasks**; execution resolves a run's assigned profile into its session configuration. For now this is a typed `agent_profile` object the master consumes and runs use; later, profiles graduate to an org-level named library (shareable, reusable across streams).
- **The seat/profile split (the load-bearing idea):** **capability comes from the profile; authority comes from the seat.** A subtask seat has the reduced surface (no creation, no proposals, no planning) no matter which profile fills it; the master seat keeps its clipped authority envelope (never approve, never touch protected refs) no matter which profile fills *it*. Charter prose can pick profiles for seats; it can never move authority between seats.
- **Portable memory** rides the profile through the existing `MemoryBackend` seam — a profile's memory travels with it across streams and machines, so a named agent accumulates competence instead of amnesia. ("Master" remains the only named seat vocabulary — owner kept it.)
- **Ripples:** A4's envelope carries `agents` (available profiles + assignment defaults per work shape) instead of per-role model fields; A8's economics happen by profile assignment; review lenses (Phase E) are profiles assigned to a review seat. Shipped surfaces say "the assigned agent" or the profile's name — never a role noun (v0 authorship rule applies).

### A12. Product surface: per-project WorkGraph + the Task Composer (owner directive, 2026-07-28)

- **Owner decision:** WorkGraph stops being one global page. It becomes the third sibling pane of every project — **Sessions · Terminals · WorkGraph** — reached exactly like the other two: the header's right-action creators (session / terminal / **task**) land on the current project's page, and switching project moves the creation context with you. Home keeps the cross-project pulse (stream cards grouped by project + the Needs-you card — both FINAL per prior owner direction, unchanged).
- **The Task Composer** replaces "new session button" ambitions at project/workspace level: a page with the same bones as the session composer, **two tabs** — **Compose** (intent box; an agent-profile picker where model/harness pickers sat, since a profile is harness+model+tools+memory; placement; optional target stream; draft toggle per A5) and **Streams** (all of this project's streams, live-filtered, so filing into an existing stream is one click and duplicate streams don't get born).
- **Experience reference:** `docs/workgraph-next.md` — the present-tense north-star description including the full UI map. Build lands with the phases (composer + per-project page are Phase B–C surface work; the swarm-visible stream page details ride Phases C–D).

### A13. Child streams — structural depth for goals bigger than one stream (extends 004 §3.2; concretized on the "port SQLite to Rust" stress test)

- **Why it exists:** one stream has one serial integrator (its master's merge queue), one size-capped notes doc, and one page a human can read. A goal like "port SQLite to Rust" exceeds all three. Planning depth is already handled *in time* (task generations — A2's depth doctrine); structural depth is handled by **promotion**: a component that is a project in its own right becomes a **child stream**. 004's flow-stream "promote to a project stream" disposition is the same verb; this generalizes it to project→project decomposition.
- **Mechanics:**
  - A stream may carry `parent_stream_id`. Promotion = an admission proposal targeting a **new** stream that carries the parent link, a **budget carve** from the parent (hard: child held when its carve exhausts; parent's budget is the sum guard), and an **envelope branched off the parent's** (child base = parent branch @ revision).
  - The child's charter is drafted at promotion and **states its interface contract with siblings** (what it exposes, what it must not change without filing up). Child gets its own master, notes, autonomy policy, and profiles — a full stream, no special-cased behavior.
  - **Born-state follows the same policy as all agent-created work**: in a supervised parent, a promotion proposal is Staged; in an autonomous parent it may auto-proceed within the compiled envelope (`may_promote`), with **hold-and-confirm on the first promotion per stream** (guardrail-5 pattern — creating a standing master + splitting budget is a structural act).
  - **Cross-stream coordination is ordinary work, not a new channel.** A child needing an interface change files a task into the parent (the ledger skill files into any owned stream); the parent's master triages it. **Integration of child branches into the parent trunk is ordinary tasks in the parent's graph**, behind the same landing gate and test oracle. Deliberately absent: any master↔master primitive.
  - **Closure rolls up:** a parent stream cannot close while a child is open (same shape as children-terminal completion elsewhere). Child escalations surface in the one Needs-you, labeled with the stream path (`parent › child`).
  - **UI stays flat:** child streams are cards with a parent chip on the project WorkGraph page; a stream page lists its children with status lines. A link, never tree navigation.
- **Depth:** promotion chains may nest (child of child) — every level is a fully legible stream, which is the point; the flat-UI and one-Needs-you invariants hold at every level.

## 3. The motion layer (new — 004 predates the CF review; full analysis in `docs/cf-reliability-scalability-review-2026-07-28.md`)

The swarm multiplies exactly the loads the review flagged. These are prerequisites, not polish; each declares its platform budget (principle 7).

- **M1 — Shard the change cursor per stream** (review A5). Today every command under one owner serializes on one Convex row; a 6-wide swarm queues on the database before anything else. Per-stream sequence rows already exist as the pattern. *Positive control: N parallel commands under one owner across K streams commit without cross-stream OCC retries.*
- **M2 — Doorbells carry cursors; snapshots are bounded** (review A5/B3, principle 9). The nudge carries the change cursor so current clients skip refetch and gapped clients detect loss; `streamRows`' eight unbounded collects get explicit bounds/paging; a slow poll or `id:`-line resume floors delivery.
- **M3 — Wake-driven recovery; the cron drains a dirty set** (review A1, principle 5). wakes-v2 (durable row first, DO nudge second) becomes the only drive path; the 15-minute sweep becomes cursor + budget over flagged-dirty tenants, never `take(500)` over everyone. The dead minute-cron gate is deleted or registered (chip filed).
- **M4 — Identity resolution cached; timeouts everywhere** (review A2/B5). One Convex round-trip per request in steady state; `AbortSignal.timeout` on every Convex/Polar/Daytona call; authority outages surface as 503, never 401 (chip filed).
- **M5 — Placement lifecycle is reaped.** Worktree/sandbox-per-attempt multiplies the leak surface; the sandbox GC no-op (review B1, chip filed) must be fixed **before** Phase C below, and worktree lifecycle gets the same leak-test 004 Phase 5 already demands.

## 4. What survives autonomy — the rails table (review gate for every phase)

| Rail | Enforced by | Autonomous stream |
|---|---|---|
| Agent-created work labeled, provenance stamped | storage (actor fields) | unchanged — labels shown, nothing to approve |
| Public-source content cannot execute | provenance ceiling (guardrail 2) | **unchanged — cannot be opened by charter or autonomy** |
| PRs draft by default; first non-draft/public = hold-and-confirm | guardrail 5 | unchanged |
| Merge/land passes the diff gate (no new `any`/`@ts-ignore`/strictness loss) | landing-integrity on the diff | unchanged |
| Protected refs unpushable | git permission fact (guardrail 1) | unchanged |
| Outcome/stream closure, public PR confirmation | owner identity | unchanged |
| Credentials never reach agents | secret-free connection metadata | unchanged |
| Runaway loops | attempt caps per failure signature, `failure_halt`, wake coalescing | unchanged + **budget cap** (new) |
| Audit | receipts + atomic audit records | unchanged — plus auto-admission events |

An implementation that ships autonomy but weakens any row fails review, per 004 §4's standing rule.

## 5. Consolidated build order

Current reality (per the primer): 004's Phase 0b (one-running-task), the approval gate, master v1 with receipts/lanes/escalations, and landing-integrity already exist; the namespace unification landed 2026-07-28. The ladder below merges the remainder of 004's phases with the amendments and motion work. Every phase inherits goal.md gates (positive controls; vision-reviewed UI evidence; single-box behavior unchanged).

**Phase A — Hygiene + prerequisites (parallel-safe, start immediately).**
The four filed chips (sandbox GC no-op; dead minute-cron; 503-not-401; relay prod config) + M1 cursor sharding + M4 timeouts/identity cache.
*DoD:* chip DoDs as filed; M1/M4 positive controls above; no behavior change in supervised flows (regression suite green).

**Phase B — Autonomy core (days of work; serial autonomous streams ship).**
A1 born-state policy consult (both backends, same line discipline as today) + A5 draft flag + A8 budget attribution/cap + hold-and-confirm on the autonomy flip.
*DoD:* E2E — in an autonomous stream, an agent-created task launches with zero approvals and the run is budget-capped; the same fixture in a supervised stream stays Staged (positive control both directions); public-source fixture stays Staged in the autonomous stream; budget exhaustion holds the stream and raises Needs-you; UI labels auto-admitted rows (vision-reviewed, both themes).

**Phase C — Parallel placement + landing funnel (004 Phase 5, extended).**
Worktree-per-task placement (charter-requested), sandbox placement option, concurrency caps from the envelope, master merge queue as the funnel, overlap flags/auto-serialization, worktree + sandbox leak-tests (M5 first).
*DoD:* 004 Phase 5 DoD verbatim (concurrent non-overlapping worktree tasks; engineered overlap serialized; engineered conflict escalates with both diffs) + a 4-wide autonomous swarm lands merged work through the diff gate on a fixture repo; zero orphan worktrees/sandboxes after stream close.

**Phase D — The execution stratum + economics.**
A2 subtasks + A11 agent profiles + A8 budgets/tier-routing + A6 multi-source proposals + A13 child-stream promotion.
*DoD:* a task fans N subtask runs onto a cheap-tier profile whose instructions are the parent's collapsed plan; a subtask run attempting to create a task is rejected server-side regardless of profile (positive control — seat authority beats profile capability); the master's assignment consumes capability briefs; roll-up completion; per-profile token/cost split visible on the stream card and consistent with usage rows. Child streams: promoting a component from a fixture stream yields a child with a branched envelope and a carved budget; the child files an interface task into the parent and it appears in the parent's graph; a parent integration task merges the child branch through the landing gate; parent closure is blocked while the child is open (positive control); child escalation shows in Needs-you labeled `parent › child`.

**Phase E — Verification + delivery floor.**
A3 evidence verification (re-run `test_result`, confirm `integration` refs) + reviewer lenses as a charter option + M2 doorbell cursors/bounded snapshots + A7 dirty-gated master wakes.
*DoD:* a fabricated passing `test_result` is marked `failed` by the verifier and blocks completion (positive control); a dropped nudge is recovered within one gap-detect interval with no user interaction; an idle open stream burns zero master sessions across 48h; contract-requires-verified enforced in autonomous defaults.

**Ordering rationale:** B before C ships the experiment earliest (owner: experimenters should be able to opt in now); C before D because sub-workers without isolation would serialize anyway; E last because its value multiplies with volume — but the A3 schema fields land in B so no migration debt accrues. 004's Phase 3 dogfood gate applies to this ladder too: after Phase B and again after Phase D, run the team's own backlog through it and record the verdict here.

## 6. Out of scope / do-not-copy

- **Recursive task nesting** (promotion instead — A2 depth doctrine; revisit only on dogfood evidence).
- **A custom high-throughput VCS** (Cursor's 1,000 commits/sec solves Cursor-scale; worktrees + the merge queue suffice at user scale).
- **Any LLM in the launch gate** (the oracle stays a pure predicate; reasons stay observability — owner, round 2).
- **Global modes** (autonomy is per-stream envelope state; `executionMode` stays deleted — this plan's A1 is not its revival, and the distinction is: policy on a stream's envelope, compiled from its charter, capped by guardrails; never a workspace-wide switch).
- **Attestation-only evidence kinds** (A3).
- **Master→running-attempt push channel** (deferred, A7).
- 004's §7 exclusions otherwise stand (tracker write-back, cross-stream memory, speculative execution, human DAG authoring, Temporal-style engines, an MCP approve tool).

3. **Sandbox placement economics** — per-attempt cloud VMs on operator keys need a cost ceiling distinct from token budget; decide whether `budget` is unified (tokens+compute in currency) or split.
4. **Reviewer lens set** — which decorrelated views ship first (transcript-blind output review vs code-only review), and whether lenses run as attempts or as a cheaper non-attempt check.
5. **Child streams** — promoted to a full amendment (A13). Still open within it: exact linkage schema fields; whether `may_promote` defaults on or off in autonomous charters; and whether nested promotion depth gets a soft cap or stays unlimited-but-observed until dogfooding says otherwise.
