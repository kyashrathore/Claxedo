## Preserved reader and cleanup contracts

Signed reader state is hosted and keyed by the authenticated user and canonical session. Unsigned local state uses the existing local user and persists across restart. Seen acknowledges only the outcome actually displayed in the visible transcript. An explicit Settle click acknowledges the outcome represented by that row, not a newer unseen result that raced the click. Keep outcome acknowledgement and settlement separate, with independently ordered reader-state updates. Meaningful new activity invalidates settlement; title changes, read writes, and duplicate status frames do not.

Use authoritative activity/outcome positions for stale-write detection and timestamps for date filtering. A complete latest-state snapshot restores dots but cannot recover every transient attention event. Preserve attention identities through producer batching and durable replay/reconciliation, including a question opening and closing within a batch. Recover missed facts silently after reconnect. Process attention for unloaded/settled sessions independently of rail visibility. A machine or cloud publisher must carry canonical status, background work, outcome, and activity data; admission, persistence, and notices must change together.

MCP cleanup reuses the server's date/reader-state query and canonical delete operation. Filter created/meaningful-activity/settled timestamps before pagination, with explicit timezone and inclusive-start/exclusive-end bounds. Report offline sources as incomplete, not empty. Make deletion callable inside a session through a server-issued user-bound capability and the existing destructive-tool approval/audit mechanism; bare runtime credentials do not gain account-admin rights. Check candidate reader state at command admission and runtime activity under the same serialization as turn admission/deletion. A session resumed since selection must conflict even when hosted status is delayed. Return exact per-target successes/failures and explain child cascades. This is logical deletion; no physical-journal erasure claim is added.

Reader revision checks linearize at cleanup command admission. A Seen or Return command committed before admission rejects the stale selection; a reader write committed afterward is a later independent command and does not revoke that admitted deletion. Actual new runtime work still conflicts under the runtime's serialized deletion guard. Delegated permission has a separate boundary: revalidate the original capability and current owner/origin/consent for each target and immediately before its runtime request, after relay lookup and token minting. Withdrawal between targets prevents the remaining deletions and preserves already confirmed receipts.

An older local session's `/s/:id` URL resolves from its canonical loaded row when available. A cold URL asks the local producer for only that session's exact workspace/project identity. The local workspace store contains this machine's own inventory; remote-machine records belong to the control plane. Missing, ambiguous, deleted or non-local identities fail explicitly. This lookup does not load extra Project pages, construct a session row, or acknowledge an outcome; normal transcript reads and visibility rules still own those facts.
