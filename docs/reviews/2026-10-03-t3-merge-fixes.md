# T3 audit: seven defect fixes

Implementation on `dev`, 2026-10-03. This addresses B1–B7 from [the applicability audit](2026-10-03-t3-merge-applicability.md), not the feature gaps in the 339-item checklist. At the user's request, the changes are committed directly on `dev` in three groups: portable handoff, child follow-up lifecycle, and queue editing. No separate merge is required; these commits have not been pushed by this task.

## Behavior and ownership

| Audit finding | Implemented change | Regression evidence |
| --- | --- | --- |
| B1: reasoning leaks into portable handoff | `renderSessionTranscript` accepts public text and terminal tool results. Reasoning, binary attachments, tool inputs and pending/running tool state are excluded. | Contract test plus a real `runtime.sessions.updateConfig` / `runtime.turns.start` harness switch. |
| B2: interrupted/failed partial work disappears | Assistant text remains in order and carries its error outcome name. | Aborted, unknown-error and rate-limit cases; actual host turn that fails after emitting public text. |
| B3: assistant rows collapse and agent authors disappear | Traverse the authoritative ordered message list, keeping every public row and `info.claxedo.author` attribution. Apply the existing bounded suffix budget afterward. | Multiple assistant rows, an intervening child wake, unanswered user messages, delimiter quoting and long history. |
| B4: later child turns never become active or wake the parent | Observe the actual admitted turn ID, correlate each run durably, and include its revision in events and snapshots. Read completion text from that turn's `parentID`. Store immutable completion results and matching delivery receipts in the existing observation journal. | Two HTTP child prompts; running status and active-child cap; late completion during a newer run; multiple pending results; aborted result; store close/reopen; stale replay; both attributed wakes in the native Claude/browser corpus. |
| B5: queue edit drops attachments | The wire adapter retains filename, MIME type, URL and synthetic text. `queuedDraft` in `composer/model.ts` restores binary files with the editable prompt, and notes as the context items the composer renders: file comments, quotes, and image-mark notes as `image-note` items (the mark is already drawn into the image). Other notes return as text items. Each note is sent again with the same text. The session screen refuses a record it cannot restore before holding it. | Image, PDF and note round-trip unit coverage; real queued-file replacement in the browser. |
| B6: queue edit destroys the unsent draft | The composer store forks the session key's draft for the edit. Producers (review comments, browser picks, quotes) and the editor write to the visible fork; the harness selection, history and the unsent draft stay on `session:<id>`. The fork is never persisted. Save and cancel drop it. | Store fork tests (writes, persistence, eviction, join); original text, image and armed Goal remain intact after a save; browser save/cancel/reload on web and phone. |
| B7: failed replacement creates a new prompt | Capture the replacement before asynchronous settings. A refused replacement rejects with an error and never sends. When a read no longer lists the edited record, the edit ends and its text joins the session's draft (replacing an empty draft, appended to one with text), so Send works again. | Refused-replacement regression, literal `/goal` edit, queue-edit lifecycle tests, and browser flows for removal by another client before Save and for a record that disappears while it is edited. |

The child lifecycle still uses the existing permission ceiling, origin/authority and turn-admission boundaries. Host-child nesting remains disallowed. Completion delivery is idempotent by the recorded assistant-message identity. A newer child result cannot overwrite a pending older result. Receipt admission computes the projected wake state transactionally, so another completion arriving during delivery stays pending.

No runtime database schema or provider wire protocol was changed. Existing pending wake records retain their established read contract; newly produced completion observations always carry their result. The new run revision is generated by durable admission, never inferred by the UI. Replays return the persisted canonical event, including that revision.
