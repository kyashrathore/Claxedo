## Reading of the classes (please sanity-check)

- **KEEP is used more broadly than races.** This scope is almost entirely pure contract code — decoders, validators, identity/equality semantics — plus a security-hardened HTTP adapter. For these, "the focused test stays next to its code" is the only honest replacement: a recorded corpus contains only *accepted* payloads, so it can never prove a decoder still *rejects* `javascript:` URLs, scope-mismatched operations or header injection; and no scripted flow enumerates credential-table consistency or leap-second handling. `recovery.ts` is explicitly kept whole in `agent-runtime-contract`, so its decoder/finalizer/dedup tests stay. Where a positive shape assertion is genuinely corpus-covered it is marked WIRE-CORPUS instead.
- **Registry-table invariants** (`harness-table.test.ts`, `harnesses.test.ts`, 22 rows) are KEEP because the *invariants* (provider-id uniqueness, connect-provider ordering, connection-identity rules, immutable identity, slug validation) must be re-expressed against the one registry that replaces the four lists — even though the files they test are rebuilt. They are not OBSOLETE: the behavior (which stored login a harness runs on, whether "connection:gemini" parses) is user-visible.
- **OBSOLETE (1 row):** `adapter.test.ts > fails unsupported interactive events…` asserts today's defect H-7 (a `permission.asked` aborts the turn as `unsupported_interaction`). The fix routes permissions through the broker and OpenCode's reply endpoints (or deletes the transport under decision 2); either way the asserted behavior goes. Note kept in the row: the abort-once discipline may still deserve a test for events that remain unsupported.
- **Decision 2 (OpenCode: server transport vs ACP) hangs over all 48 adapter-package rows.** Classified as if the transport is kept; rows that hinge on it carry a note. If ACP wins, the trust-boundary KEEPs (secrets-never-follow-redirects, cleartext refusal, immutable identity, header allowlists) should re-attach to whatever provider/remote-harness validation remains — they are not OpenCode-specific ideas.

## Surprises

1. **This lane is dominated by KEEP.** 76% of cases are focused tests of pure contract code the plan keeps (recovery.ts whole; the rest of `agent-runtime-contract` stays as the shared wire contract ≤3.5k). If the intent was for the corpora to absorb more of this, the gap is negative-path validation: the corpora record accepted shapes only. Deleting the decoder-rejection tests would leave P-40/P-42 security fixes without a guard.
2. **The `unsupported_interaction` test is the defect, not a guard** — the only row where the plan intentionally changes the asserted behavior (H-7).
3. **`claims.test.ts` has no natural replacement class**: pure credential-claim decoding, used by server-core and local-server, never on the presentation wire — marked KEEP throughout.
4. **`harness-table.ts`/`harnesses.ts` tests look deletable but aren't**: the tables merge into the registry, and the invariants they pin (provider-id uniqueness, connect-provider-first ordering — both landed as fixes bd340bb2b9/873f7fbd3f/2059244f06) are exactly the credential-routing behavior C-12 cares about.
5. **Two "fix" commits are merges** whose subjects only mention `fix/` branches; they add no unique unguarded change.
6. **package-boundary.test.ts is a hand-rolled ratchet** — its three cases are subsumed by the plan's transport-boundary check, the cleanest KEEP-as-ratchet in the map.
