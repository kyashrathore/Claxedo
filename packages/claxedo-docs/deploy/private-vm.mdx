---
title: "Private VM"
description: "Run a workspace runtime on a private network."
---

Run `@claxedo/workspace-runtime` on an operator-controlled VM, pinned to one
workspace target, behind private ingress such as a VM firewall or security
group.

## Start a private-network runtime

```ts
import { privateNetworkWorkspaceRuntimeExposure, startServer } from "@claxedo/workspace-runtime"

startServer(4096, {
  exposure: privateNetworkWorkspaceRuntimeExposure({
    name: "private-vm-ingress",
    guard: (input) => input.request.headers.get("x-private-ingress") === process.env.PRIVATE_INGRESS_TOKEN,
    runtimeAuth: (input) => input.request.headers.get("authorization") === `Bearer ${process.env.WORKSPACE_RUNTIME_PRIVATE_TOKEN}`,
  }),
  target: {
    workspaceId: "ws_private_vm",
    directory: "/workspace/repo",
  },
})
```

This creates a runtime pinned to one workspace target. Network access control is
provided by the surrounding private network.

<Warning>
A private-network exposure must supply **both** a host `guard` and `runtimeAuth`.
The private-network exposure does not emit runtime CORS headers by default —
your trusted ingress owns the browser origin policy.
</Warning>

## Binding to a non-loopback host

`startServer()` defaults its listen host to `127.0.0.1`. To bind a private
interface or `0.0.0.0`, one of these must be true:

- Relay-host auth is configured, **or**
- A private-network exposure supplies both host guard and runtime auth (above),
  **or**
- The operator explicitly sets
  `WORKSPACE_RUNTIME_ALLOW_UNAUTHENTICATED_NON_LOOPBACK=1`.

<Warning>
The `WORKSPACE_RUNTIME_ALLOW_UNAUTHENTICATED_NON_LOOPBACK=1` opt-out is the
`private-network-dev-unsafe` path. It is **only** for self-managed deployments
behind trusted private-network controls and adds no application-level auth. It
does not add any auth to host routes.
</Warning>

## Config token vs management auth

`WORKSPACE_RUNTIME_CONFIG_TOKEN` is a trusted direct token for relay-host
middleware and the health check (`GET /api/wr/health`) — not whole-server auth
and not config-mutation auth. Config mutation is authorized only by an explicit
workspace-runtime management adapter; it does not authorize PTY, process, file,
session, or VCS routes.
