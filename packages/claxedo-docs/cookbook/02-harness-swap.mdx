`runOnce()` below never mentions a vendor. Claude, Codex, and Cursor all run
through the identical code path — swapping agents is swapping one string.

## Run

```bash
bun run recipe:02-harness-swap
```

<Note>
Needs at least one coding-agent CLI installed **and** authenticated. The
recipe runs every harness it detects as ready, and honestly lists the rest as
skipped with the reason.
</Note>

## The moat: one function, any agent

```ts
// Nothing in here is claude-specific, codex-specific, or cursor-specific.
async function runOnce(harness: { id: DetectedHarness["id"]; access: DetectedHarness["access"] }) {
  const dir = await mkdtemp(path.join(tmpdir(), `claxedo-swap-${harness.id}-`))
  await writeFile(path.join(dir, "README.md"), "# harness-swap scratch\n")

  const runtime = createAgentRuntime({
    store: createMemoryRuntimeStore(),
    harnesses: [harnessFactory(harness)],
  })
  try {
    const session = await runtime.sessions.create({
      directory: dir,
      harness,
      model: { providerID: harness.id, modelID: "default" },
      title: `swap ${harness.id}`,
    })
    const events = runtime.events.subscribe({ sessionId: session.id })
    await runtime.turns.start({
      sessionId: session.id,
      agent: "",
      text: `Reply with exactly: HELLO FROM ${harness.id.toUpperCase()} VIA CLAXEDO`,
    })
    const turn = await waitForTurn(runtime, events, dir, 120_000)
    const reply = assistantText(await runtime.events.list(session.id))
    return { turn, reply }
  } finally {
    runtime.dispose()
  }
}
```

## Lift this into your app

`runOnce()` is the pattern: keep the harness id/access pair as data (a user
setting, a per-session field), register the matching factory, and everything
downstream — sessions, turns, events, transcripts — stays vendor-agnostic.
The auth probes are worth stealing too: binary-on-PATH is not the same as
logged-in, and an unauthenticated CLI fails mid-turn with a masked error.
