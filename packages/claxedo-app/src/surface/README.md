# Surface

The native renderer for declarative UI: A2UI v0.9 messages over the Claxedo catalog (`@claxedo/plugin-api/surface`), drawn with the app's own kit components. One renderer serves both producers: an agent's `ui_show` reply in the transcript (`src/transcript/surface-reply.tsx`) and app plugins.

## Owned concepts

- **Surface** (`store.ts` `createSurface`): one surface id, its lifecycle, its component registry and its data model, all plain Solid state, so it can be created outside a component. `apply(message)` takes one A2UI message: it parses it against `surfaceMessageSchema` and throws `SurfaceMessageError` for a malformed message, a message addressed to another surface, an update before `createSurface`, or a second `createSurface`. The public type carries only `surfaceId` and `apply`; the view reads the state through the module's `surfaceState` symbol.
- **Lifecycle** (`model.ts` `surfaceLifecycle`): `waiting` → `live` on `createSurface`; `live` → `deleted` on `deleteSurface`, which also empties the registry and the data model; `deleted` → `live` on a new `createSurface`.
- **Component registry** (`component-registry.ts`): one store keyed by component id. `updateComponents` upserts each definition with `reconcile(..., { merge: true })`, so a definition keeps its proxy, an untouched component re-runs nothing, a changed prop re-runs only its readers, and a prop the new definition leaves out is dropped.
- **Data model** (`data-model.ts`): one store per surface. A write at a JSON Pointer (`data-path.ts`) sets exactly that path: `/` (or no path) replaces the whole model, which must be an object; a missing intermediate is created as an object; a write with no value deletes the key, or removes the list element and closes the gap. Objects and lists are written with `reconcile` so only the leaves that changed notify. `snapshot` returns a detached plain copy.
- **Bindings** (`binding.ts`): a prop is a literal or `{ path }`. Each binding reads exactly one path with property access, so a patch to `/items/3/title` re-runs only the readers of that path. An absolute path starts at the root; a relative path resolves inside the template item's scope. Input fields bound to a path write back into the data model locally, with no message per keystroke; a literal value is the field's initial value, kept in the field.
- **Templates** (`view/surface-children.tsx`): `children: { componentId, path }` iterates the list at `path` with `<Index>`, one stable child per index, whose scope is that item's path.
- **Actions** (`action.ts`): a Button's `action.event` resolves its `context` when it fires (a literal, or a path's current value, copied) and reaches `SurfaceView`'s `onAction` as a `SurfaceActionEvent`. Without `onAction`, or with `actionsDisabled`, buttons are disabled.
- **Catalog views** (`view/component-views.ts`): one view per catalog component, each a kit component through `@/ui` where one fits: Text, Markdown and Code (the transcript's `Markdown`), Icon (`icon-names.ts` sends each catalog icon name either to the kit icon that means the same thing or to the surface's own glyph in `view/surface-glyphs.tsx`, drawn in the kit's 20-unit outline style and sized by the kit's icon classes; `view/surface-icon.tsx` draws both, and a Button's or ListItem's icon may be bound so a toggle shows its state), Badge (`Tag`), Link (http and https only, opened like a transcript link), Row, Column, List, Grid, Card, Tabs, Collapsible, Divider, Button, TextField and Textarea, CheckBox, Switch, ChoicePicker (radio group, select, segmented control, checkboxes or chips), Slider and DateTimeInput (native inputs), Progress, Spinner, Table, DiffStat (`DiffChanges`), EmptyState, and the page and summary primitives: Header, Section and Footer (`view/page-views.tsx`), Stat, Callout and KeyValue (`view/summary-views.tsx`) and ListItem (`view/list-item-view.tsx`). `weight` on a direct child of Row or Column is its flex-grow. A TextField's `validationRegexp` must match the whole value; a pattern that does not compile validates nothing and is logged.
- **Display rules** (pure, tested): `grid-columns.ts` turns a Grid's `columns` into its `data-columns` hook (default 2, clamped to 1–6); `key-value.ts` keeps the labelled rows of a KeyValue's literal or bound list; `table-alignment.ts` right-aligns a Table column whose present values are all numbers; `range-fill.ts` places a Slider's value on its track; `tones.ts` maps Badge tones onto the kit `Tag` (success, warning and danger restyle a neutral tag) and gives each Callout tone its icon.

## Design defaults

Every surface looks consistent by construction; authors choose structure, never spacing or colour. All colours are v2 tokens, so light and dark both hold. The stylesheets split by concern: `surface.css` (the frame, source mark and text scale), `surface-layout.css` (flex, Grid, Card, Section, Header, groups), `surface-fields.css` (buttons and inputs) and `surface-display.css` (badges, Stat, Callout, KeyValue, ListItem, Table, Progress, EmptyState).

- Every surface is a size container named `surface`; the narrow-width rules below apply under 480 px of surface width, wherever the surface is drawn.
- The source mark (`view/surface-source-mark.tsx`) is an eyebrow above the content: the producer's glyph and "{name} · agent reply" or "{name} · app plugin" (`i18n.ts`), 12 px muted.
- Header is a grid: icon, title with its badges, and actions on the title line, the subtitle below cut to one line (two when narrow) with the full text in its `title`. Narrow, it reflows to icon and title, subtitle, badges, then the actions on their own row under the title.
- Callout `action` draws its Button at the right (under the text when narrow); `dismissible` draws a close button that hides the Callout for this view until its id, title or text changes.
- Row actions (`view/row-actions.ts`): a template marks its children as repeated. A repeated ListItem draws its `primaryAction` as a compact neutral button and its `actions` as icon-only ghost buttons (the label stays as the accessible name and `title`), invisible and inert until the row is hovered or holds focus when the primary pointer is a fine, hover-capable one, and always shown otherwise (touch). Their space is always kept, so nothing moves or is covered on hover: a wide row keeps them in a trailing cluster level with the title, a row under 420 px puts its actions at the end of its `meta` line, centred with the badges, wrapping to their own end-aligned line only when the two do not fit or the row has no `meta`.
- A ghost button at the start of a Footer's `start` group, or of a narrow Header's actions, and one at the end of a Section's actions, is pulled out by its own padding so its text lines up with the content edge. A Button without an icon stays a compact neutral text button. A Button whose `icon` is `delete` turns red on hover and focus. A ListItem that is not repeated shows every action at full size.
- `borderless` is a neutral ghost button; the accent colour belongs to Links and the primary button. A default button's hover is a light layer tint with a stronger edge, so it never reads as disabled.
- Tabs inside a surface do not clip their content, so a row's hover background and edge buttons stay whole. A tab strip wider than the surface fades the edge that hides tabs (`tab-strip.ts` names the edge from the strip's scroll position) and scrolls the selected tab into view.
- An empty List or Grid draws nothing and takes no gap. Code wraps long lines. A long-text field grows with its text in whole lines. A Section's header actions stay right-aligned, wrap under the title when they do not fit beside it, and cut a label too long for the width with an ellipsis.
- A Grid's narrow-width collapse depends on what it holds: only Stats keep two columns on a phone; Sections or Cards go to one column under 560 px.
- A Collapsible nested in a Section, Card or row uses the 13 px medium row weight; one at the top level uses the Section-title weight. Its hover fill stays inside the content edges.
- `borderless` buttons are medium weight in the muted text colour, with a faint fill on hover.
- Collapsible draws as a full-width disclosure row in the Section title's type, with a leading chevron that turns when open.
- A weighted child of a Row keeps at least 8rem before the Row wraps it.
- ListItem: the item is its own size container (`surface-item`); under 420 px its actions take their own row and wrap. The icon and actions align with the title's first line; `meta` sits under the subtitle and wraps; actions keep their own column and wrap as a group under the text when they do not fit. The title is cut to one line (two when narrow), the subtitle to two, each with its full text in `title`.
- A Table under 480 px stacks each row into label and value lines (each cell carries a label hidden on wide surfaces).
- On a coarse pointer every surface button is 36 px tall; the surface opts out of the shell's 44 px icon-button rule (`data-claxedo-compact-touch`) so buttons in a group stay equal.
- Footer is the closing action bar: `start` on the left, `end` right-aligned with the primary Button last. Inside a card Section or Card it draws a top divider; when narrow the `end` group spans the width first, its buttons equal, and the `start` group takes its own row below.
- Spacing on a 4/8 px scale: Column gap 12, Row gap 8, Section gap 12, Grid gap 8/12/16 (`small`/`medium`/`large`), Card and Section padding 16.
- Text scale: h1 22/600, h2 18/600, h3 15/600, h4 13/600, h5 12/600 uppercase muted, body 13/400, caption 12 muted. Header titles are 18/600, Section titles 14/600.
- Buttons keep their intrinsic width in a stretching Column or a Grid cell unless they carry `weight`. Primary is the kit's contrast button, default its neutral button, borderless a ghost button in the accent colour with a hover background. A Button's `icon` draws before its label.
- Badges and ListItem meta keep the kit `Tag` shape (small radius); a tone only recolours it. ChoicePicker chips are segmented-control toggles with the kit's radius that wrap and never cut their labels.
- Stat captions wrap to two lines under 480 px instead of being cut.
- Stat tiles share one structure: label, value and a footer line that is always present (delta, then caption, on one baseline), pinned to the bottom so tiles in a Grid row are equal height. A delta is text coloured by its tone, never a pill.
- The Slider is a 4 px track filled in the accent colour with a small round thumb and a fixed-width tabular readout; Progress is a 4 px bar with no thumb under its label and value.
- Every field label (TextField, Textarea, ChoicePicker, Slider, DateTimeInput, a radio group) is 12 px medium muted, 4 px above a control that fills its column; CheckBox and Switch are toggle rows with the control before a 13 px label.
- Card and `card` Section: 1 px muted border, 10 px radius, a layer-01 background; a card, Stat or card Section inside one drops back to the base background.
- Grid columns collapse inside the Grid's own container: 5–6 become 3 under 720 px and 2 under 480 px, 4 become 2 under 560 px, 2–3 become 1 under 480 px.
- Tables: 12 px muted headers, 13 px rows with dividers, cells on one line inside a horizontal scroller, numeric columns right-aligned.
- A Column or List of ListItems drops its gap; rows are divided by a 1 px rule and a selected row (`aria-current`) has only a faint accent tint, never an edge bar.

## Invariants

- Nothing draws until the surface is live and a component with id `root` exists. A child id with no component draws nothing until it arrives.
- Every surface draws inside `[data-component="surface"]`, which carries its source (`data-source`, agent or plugin) and shows an eyebrow naming the producer and whether it is an agent reply or an app plugin, in every theme. No catalog component draws an overlay, a dialog or a toast, and none looks like a permission or question request.
- Markdown and Code use the transcript's markdown pipeline, so a surface needs `TranscriptKitProviders` above it.
