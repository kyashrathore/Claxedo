# Files

Owns: the Files navigator and the file tab the workspace panel shows, and the session the panel tools send context to.

## Owned concepts

- **Active session** (`location.ts`): the session the URL names (`/w/:placementId/session/:sessionId`), as a full `SessionLocation`. Review comments, file comments, quoted comments from a Markdown preview and browser picks go into that session's composer draft. The placement the panel shows is the shell's `useShellRoute().placementId`.
- **Files navigator** (`view/files-navigator.tsx`): v1's search row over v1's tree. The file open in the panel is expanded to (`FilesProvider`), scrolled into view by the tree once its row exists, and highlighted.
- **Search view** (`search-view.ts`, `search-query.ts`, `search-tree.ts`): the query is the field's text 150 ms after the last keystroke (at once when it is emptied or the placement changes). `server.queries.files.search` (files only, as v1) answers it; the tree then shows only the matches and their folders, built from the result's own paths, so no folder is listed while searching. As in v1, every folder of a result is expanded in `FilesProvider` and stays expanded after the search is cleared; the listings of those folders are read once the field is empty. A result with the same paths as the one shown, in any order, changes nothing. Escape or "Clear search" clears it, and the tree stays mounted meanwhile.
- **Tree** (`tree-rows.ts`, `view/file-tree.tsx`, `view/file-tree-row.tsx`, `view/file-tree-keys.ts`, `view/file-tree-node.tsx`, `tree-source.ts`, `tree-helpers.ts`): one `server.queries.files.tree` query per expanded directory through `keyedQueries` (`src/lib/keyed-queries.ts`), read by directory rather than by position, so collapsing or expanding a folder never hands another level's listing to a directory; sorted folders first. `treeRows` turns the source, the expanded folders and each level's reveal batches into one ordered list of rows (a file or folder, Show more, loading, a load failure, a repeated folder), and the tree draws only the rows in view (`@tanstack/solid-virtual`, 2 px apart, keyed by path), so a tree of hundreds of open rows costs what is on screen. Rows are 24 px: a chevron for folders, a grey file icon, the name, and the change mark from `server.queries.git.status` (A/D/M for files, a dot for folders). Each level shows 24 entries around the active file with "Show 24 more" on either side. Arrow keys move by row index and scroll the target into view before focusing it. A reveal or a key move scrolls only when the row is out of view (the virtualizer's `getOffsetForIndex` answers `auto` for a row in view): `scrollToIndex` otherwise writes the unchanged offset, a forced layout in the click that opened the file. Expanded folders, each level's reveal batches, the search text and the tree's scroll position are kept per placement by `FilesProvider`, so a remounted tree shows the same rows at the same place. A level that fails to load says "The files could not be loaded" with Retry.
- **File tab** (`view/file-tab.tsx`): v1's panel file viewer for `{ placementId, path }`, with a relative workspace path or an absolute local-artifact path. Text renders in the transcript's `File` viewer, which highlights, virtualizes, reveals and selects the focus line. Markdown renders by default; "Show source" flips it per path, kept per placement by `FilesProvider`. Images are previewed, binary files say so, a read failure shows its message. "Copy path" portals into the panel's L2 row.

## Invariants

- Trees, contents, search results and status are the adapter's query data, refreshed only by its `filesChanged` invalidation. Nothing here copies them.
- Only `src/server/` turns a placement into a directory. Relative file paths use its workspace queries. Absolute artifact paths use `useFilesApi().content` and the desktop's `readFileContent` bridge, only for placements on this computer; remote and browser clients cannot read the desktop filesystem. Both producers use workspace-runtime's canonical file-content reader. Artifact tabs follow the workspace file tab's in-memory lifetime and do not expand the workspace tree.
- A focus line is re-applied for 5 s after the focus request, because the viewer's rebuilds can reset the scroll position right after the first reveal.
- The navigator's search input removes itself from the document on cleanup (`releaseChromiumAutofillAnchor`). Chromium's AutofillAgent keeps a persistent handle on the last focused text field until an element that is not a form control takes focus; the autofocused search input is that field, so an unmounted navigator stayed reachable from it (rows, shell, scroll view) as a detached tree until the composer was focused. Removing the input cuts the tree loose: measured over 5 unmounts, 0 navigator nodes retained, DOM after GC flat at about 2990.
