# Marketplace

Owns: the Marketplace page (`MarketplacePage` at `/marketplace`, which the rail registers as `marketplacePage` in the shared page tab): the directory of agent plugins (skills and MCP servers installed into agent sessions; app plugins are `src/plugins/`), a plugin's detail pane, the install sheet, plugin sources, and the read-only list of what each harness installed by itself. The catalog, activation precedence, materialization and runtime reconciliation belong to the server (`/api/claxedo/plugins`); this domain reads through `queries.marketplace` and writes through `server.marketplace` (`src/server/marketplace.ts`).

## Concepts

- **Catalog** (`MarketplaceCatalog`): `queries.marketplace.catalog()`, read without a project: every `PluginCandidate` (manifest, source, skills, MCP servers, tool groups, activation per harness), the catalog `revision`, `supportedHarnesses` and the invalid entries. It lives in the TanStack Query cache. The directory rereads it each time the page mounts (`refetchOnMount: "always"`) and keeps the previous answer on screen meanwhile. Refresh makes the server re-read its sources (`server.marketplace.refresh()`) and writes the answer into the cache; every other write invalidates every catalog and the source list (`refreshAll`). Presets' cloud capability picker reads the same catalog (`src/tasks/presets/capabilities.ts`).
- **Revision** (`revision.ts`): every write carries the catalog revision it was decided on. `withCurrentRevision` re-reads the catalog on a `conflict` and retries once, only if the revision moved. Several subjects (every tool group of the built-in plugin) are written in turn, each with the revision the previous change returned. The install sheet sends the revision it opened with and shows a conflict as its error.
- **Plugin status** (`model.ts`): installed means active for at least one harness (`effective.effective`). `pluginStatus` derives one line: the built-in plugin's groups (on, off, none on); otherwise, for an installed plugin, artifact unavailable (critical), an MCP server needing OAuth (warning), update available, else "Installed · N harnesses"; a plugin not installed says Update available or nothing. `activationSummary` says Enabled or Disabled and who decided (`effective.winner`: a project or user default is "your choice", then organization, Claxedo, this computer).
- **Directory** (`createDirectory` in `directory-state.ts`, `sections.ts`): search (name, description, skills, MCP servers, tool groups and tools), a source chip and a category chip filter the candidates, and `directorySections` splits them into Needs attention, Installed (the built-in plugin included), Featured (only under All categories), one section per source in the source list's order, and No longer served by a source. Source chips come from `queries.marketplace.sources()`, or from the candidates' own sources when that read fails or is empty. A category chip shows only when some candidate carries it. The query, filters and selection are component state; arrow keys move focus between cards and Escape closes the pane.
- **Activation** (`actions.ts`): a plugin's choice is on, off or cleared (`null`, "Clear my override", which follows the organization default when any harness has one, else Claxedo's; the menu says which before you pick, from `defaultOutcome`), sent through `setActivation` for every supported harness. Disabling confirms first, because it removes the plugin's config and materialized files. A change the server saved but could not reconcile into the runtime toasts "Activation saved" with the reason; a refused change toasts. One plugin is pending at a time.
- **Add** (`install-sheet.tsx`, `install-sections.tsx`): a plugin that is not installed and has no retained bytes opens the sheet: the fixed scope (every environment, every project on this machine) and a harness choice that preselects each harness the plugin serves with its artifact available. A plugin whose bytes are retained (`retainedDigest`) is enabled directly instead and stays usable when its source is gone; one with neither a source nor retained bytes cannot be added.
- **Built-in plugin** (`builtIn`): Claxedo's own tools as tool groups, in `BUILT_IN_TOOL_GROUP_ORDER`. It is never added, updated or cleared. Each group has its own switch (an explicit choice on the group's `pluginInstanceId`); turning the plugin on clears every group's choice so each follows its default, and turning it off, after a confirm, sets every group off. Group changes reach sessions started afterwards.
- **Details panel** (`view/details-panel.tsx`): one Details tab over the generic `SidePanel`, `SidePanelSlot` and `SidePanelHeader` from `@/ui`, with shared resize, maximize, close and motion. The slot mounts in the shell’s full-height `SidePanelArea`, beside the app toolbar, so Details and its close toggle align with workspace tabs. The active page owns the slot; returning to a session removes it and restores that session’s workspace panel. No add-tab control or workspace navigator appears. Selecting another plugin or personal entry replaces the content in that tab. `plugin-details.tsx` renders the identity, facts, notes, main action, overflow menu (Clear my override, and Update when `updateAvailable`), skills, then MCP servers or built-in tool groups. A skill opens its `SKILL.md` in place (`queries.marketplace.skill`, front matter stripped by `skillBody`), read once and never refreshed; Escape goes back, while changing plugins resets the skill selection. An MCP server shows its authentication (public, local, handled by the harness, OAuth, unavailable); this page does not connect OAuth. The panel resizes from 360 px to 60 % of the page (420 px by default) by pointer, arrow keys (24 px) or Home/End. It fills the available area on a phone or when maximized. The chosen width remains a `persistedSignal` under `claxedo:marketplace:detailWidth` in this browser's localStorage. Closing clears selection and restores the normal width for the next opening.
- **Source** (`source-actions.ts`, `add-source.tsx`): a public GitHub repository (`owner/repository`, optional ref) whose top-level folders are plugins. The server checks it on add, and a refusal (`PluginSourceError`) lists each bad file's diagnostic. A source the server marks `canRemove` can be removed while its chip is selected, after a confirm; plugins installed from it stay installed, and the filter returns to All.
- **Personal** (`personalEntries`, `personal-details.tsx`): what each harness installed on this machine by itself (`queries.marketplace.machineInstalled()`): its plugins not owned by Claxedo, and skills. Read-only, because the harness manages them. They show under All or the Personal chip, never under a category or another source. They use the same Details panel as catalog plugins. The read happens once; an install through this page does not refresh it.

Flow 12 (Marketplace opens in the page tab it shares with Tasks, and Details resize, maximize, close and replace selection), and flow 33 (full-width phone Details and touch controls).
