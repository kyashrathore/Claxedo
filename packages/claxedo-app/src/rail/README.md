# Rail

Owns: the main sidebar's content (`MainSidebar`), ported from today's app's rail: the global rows (Tasks, Marketplace, then any plugin's `sidebarItems`), the Projects tree with each project's sessions nested under it, today's account card in the footer (`AccountCard`) with a Usage button beside it (the owner's 21:10 rail foot: no separate Settings row; Settings is in the account menu and on ⌘,); and the workbench header's compact tabs (`CompactSwitcher`). The shell draws the rail's frame around it (`src/shell/view/sidebar.tsx`: the `rail-sidebar` nav, its header strip with Hide/Pin Sidebar, the resize grip).

## Concepts

- **Project sections** (`project-sections.ts`) come from `useProjectList()` (`src/projects`): today's sidebar project list, in its order. A section opens its project's draft at the project's folder placement (`server.placements`, matched by `projectId`, never by a folder path). A project with no placement in the catalog, or none that still exists (a gone folder, a failed cloud workspace), is dimmed. A cloud workspace whose sandbox is stopped is not: rows and projects look the same whatever their sandbox's state (DECISIONS, owner 16:20).
- **Rail rows** (`RailRow` in `model.ts`): a project's rows are its terminals, then its sessions, as today. `ProjectRows` renders `RailTerminalRow`s keyed by `terminalRowKey`, then one `RailSessionRow` per session id, each reading only its own row through `list.view(sessionId)`, so a status or title change re-renders that row alone. Terminals come from `useTerminals()` (`src/terminal`) for every placement of the project, retained while the project is listed; a click opens the terminal's pane, and its close ends the PTY. A project opens when it has terminals, as today.
- **Session rows** are a read-only projection of `useSessionStores().list`: the project tree groups `list.order()` (the visible rows' refs, which change only when a row joins, leaves or moves) by `ref.projectId` (`sessionIdsByProject`); archived rows and subagents never show (subagents are panel tabs). The session list store owns rows, order (`human_turn_desc`) and status; the rail never fetches, orders or patches them.
- **Paging**: a project shows 5 rows, and "Load more" shows 5 more, asking the store for its next page when the loaded rows run out. The store pages the whole list, so there is no per-project total.
- **Selection**: the active project, session and terminal rows are the ones the focused pane shows (`workbench.selectors.shownContent()`), while the route names a workspace. During a switch the pane keeps the previous session until the next one is laid out, and the rail changes with it in the same frame. Settling an open session keeps its conversation open.
- **Navigation status** (`model.ts`): canonical session attention and the reader's persisted acknowledgement determine the marker. Waiting requests and unseen failed results draw a blue dot, unseen completed results a grey dot, working a spinner, and seen idle results no mark. Unavailable execution suppresses stale live markers while persisted reader facts remain intact. Activity rows give the marker an accessible label; a row whose status cannot be read says Status unavailable and exposes the server's reason.
- **Age**: `createdAt` as a compact age ("<1m", "2h", "3d"), refreshed by the app's one age clock (`useAgeClock()` from `src/lib/clock.tsx`) at the instant the label's text changes and never while the page is hidden; the palette's session ages and the accounts' checked ages read the same clock.
- **Engagement** (`hover-engagement.ts`): project-header actions mount while the pointer or keyboard is on them. Session checkmarks appear when the pointer or keyboard engages the row. `navigation-row.css` owns the shared session and terminal fill, composing the theme's brighter row hover tint over the sidebar base for hover and selection. The action overlay inherits that exact flat fill to cover each full row right edge, with no edge fade, shadow, blur or opacity transition. The inset checkmark retains visible hover and focus feedback. It preserves title geometry and replaces the age while engaged. Measured session wrappers retain the Projects tree's original 2px spacing and Activity's 4px gap without hover reflow. On a phone or a coarse pointer the checkmark stays visible with a 44px target.
- **Long row titles** (`view/session-navigation-title.tsx`): native ellipsis keeps resting rows compact. Only the hovered row measures its actual title and action geometry. An overflowing title makes one CSS transform pass after a 650ms delay at a steady 35px per second, stops with its ending clear of the right action area, and resets on exit. Fitting titles, touch rows, and reduced-motion preferences stay static. Keyboard activation focus reveals the full title in the bounded tooltip; placement and settlement focus show their own tooltips instead. There are no frame loops, repeating animations, or per-title resize subscriptions.
- **Compact tabs** (`CompactSwitcher`, `switcher-items.ts`): today's strip in the workbench header while the sidebar is unpinned. One tab per alive workbench content in insertion order (sessions, drafts, terminals, plugin panes; files are panel tabs), titled by its pane kind, with the project's outline avatar (or the ring spinner while working, the background mark while it runs in background, a corner dot when it needs you), a hover card (title, project · workspace, status), a close button and middle-click close. A click shows that content at once; the active tab scrolls into view. Holding ⌘ for 500 ms shows each tab's `claxedo.surface.N` keybind when such a command is registered.
- **Account card** (`account-card.tsx`): today's card and menu over `useAuth()`. Signed in, it shows the avatar and name; while signing in, a spinner and "Signing in…"; while a signed desktop account's name is still being looked up, a spinner beside "Signed in"; otherwise "Sign in" when `useAuth().offered(capabilities.signedIn)` says the binding can sign in (the web: the server issues sessions; the desktop: a signed-capable build), else today's local "Not signed in" with the monitor mark. The trigger is a sidebar row: it has no fill at rest, only while hovered, focused or open. The menu holds Usage (Settings → Usage), Settings, Help, then Cancel sign in, Sign in or Log out; a failed sign-in or sign-out toasts. Today's organization switch is not ported: the adapter has no route for the user's organizations.
- **Where a session lives** (`sessionMarker`): a row whose placement is a cloud workspace, another machine or a worktree carries today's trailing icon (cloud, server or worktree) named "Cloud environment · {name}", "Another machine · {name}" or "Worktree: {project} / {name} · {path}"; a session in the project's folder on this machine has none.
- **Dragging a row** (session or terminal) onto the workbench opens or splits it there, as today: the row is a `navigation-row` drag source whose content is opened unfocused when the drag starts (`workbench.open(kind, state, false)`); released back over the rail, it just opens.
- **Opening a session** pushes today's URL: `/s/<id>` for a session on this machine's folders and worktrees, `/w/<ws>/session/<id>` for a cloud or another machine's workspace, so Back returns. `NavigationRow` closes the phone drawer after activation, including when the selected session is already open and no URL changes.
- **Row actions**: Settle writes the exact activity and reader revision through the session list owner and immediately excludes the row from both sidebar views. Running, waiting, and unavailable sessions cannot be settled. The context menu contains Copy session link, Rename when ownership permits it, and the same settlement action. It stays within the viewport and supports arrow keys. Canonical Return and deletion remain available through the authorized MCP tools.
- **Sidebar view**: Projects is the initial view. The Projects or Activity heading below global navigation holds the filter button at its right edge. Dim controls appear on sidebar hover or focus and stay visible on touch. SessionFilterMenu chooses Projects or Activity and exposes the Hide working statuses checkbox through ShellLayout. Activity is one paged active-only list across authorized projects, ordered by the same human-turn rule as Projects. Rail reads reference windows and list.view(); it owns no session cache. Shared sessions appear once in Activity; Projects retains its separate Shared with me presentation.
- **Activity context** (`view/activity-placement.tsx`): the primary line is the session title and status, with regular title weight even when selected. The muted second line holds the safe project name, its small local, machine, or cloud glyph, and the right-aligned checkmark. The glyph appears on row hover or focus and stays visible inside a 44px target on touch. Its tooltip exposes the canonical machine or cloud-workspace name on pointer hover, keyboard focus, and through its accessible label. Scoped tooltip content wraps within 260px or the available viewport width; Settle tooltips stay short while their accessible labels retain the session title. This presentation reads only authorized metadata on the canonical row. Missing metadata says unavailable; cached catalogs, paths, repository names, and placement labels never substitute for it.
- **Activity lifecycle**: Working, waiting, unseen and failure indicators update on the same card. Seen acknowledges an outcome without moving the card. Settle excludes it before server pagination; a newer meaningful activity position invalidates settlement. Only the human-turn sort key changes order. Activity does not query or display settled rows.
- **Activity layout** (view/activity-view.tsx, view/activity-rows.tsx): one scrolling region fills the pane below the heading. It has a delayed loading state, a ready empty state, and one aligned 12px failure indicator with Retry. The account footer stays outside it. No group headings, counts, folds, entrant previews or split height allocation remain.
- **Navigation performance and focus** (view/session-navigation-rows.tsx, navigation-geometry.ts): more than 100 loaded rows are virtualized against the sidebar scroller. Activity reads its row height from CSS before mounting the virtualizer; ResizeObserver updates geometry. Arrow keys and Home/End reveal rows before focusing them. Status and reader changes retain the keyed row and keyboard focus.

- **Activity filter** (view/activity-filter-toggle.tsx): while Hide working statuses is checked, a button left of the filter menu cycles Activity, Working and Needs you and changes the heading. Its icon names the next destination: dotted circle for Working, bell for Needs you, and activity pulse for Activity. Inventory owns the transient choice and resets its page on a change. Local and hosted SQL filter canonical work/pending-input before pagination; live row filtering uses the same contract. Unchecking Hide working statuses resets Activity.
- **Working visibility** (view/session-filter-menu.tsx): the checkbox saves hideWorkingStatus in principal-scoped shell preferences. CSS hides foreground and background Working marks at rest, reveals them on row hover or focus, and disables hidden animations. Waiting, errors, unseen facts, ordering, delivery and runtime state are unchanged.
