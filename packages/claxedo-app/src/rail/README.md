# Rail

Owns: the main sidebar's content (`MainSidebar`), ported from today's app's rail: the global rows (Tasks, Marketplace, then any plugin's `sidebarItems`), the Projects tree with each project's sessions nested under it, the footer's Settings row (gear and the word, the owner's 2026-10-05 A19: Settings must be visible without opening the avatar menu) above today's account card (`AccountCard`); Settings is also in the account menu and on ⌘,; and the workbench header's compact tabs (`CompactSwitcher`). The shell draws the rail's frame around it (`src/shell/view/sidebar.tsx`: the `rail-sidebar` nav, its header strip with Hide/Pin Sidebar, the resize grip).

## Concepts

- **Project sections** (`project-sections.ts`) come from `useProjectList()` (`src/projects`): today's sidebar project list, in its order. A section opens its project's draft at the project's folder placement (`server.placements`, matched by `projectId`, never by a folder path). A project with no placement in the catalog, or none that still exists (a gone folder, a failed cloud workspace), is dimmed. A cloud workspace whose sandbox is stopped is not: rows and projects look the same whatever their sandbox's state (DECISIONS, owner 16:20).
- **Rail rows** (`RailRow` in `model.ts`): a project's rows are its terminals, then its sessions, as today. `ProjectRows` renders `RailTerminalRow`s keyed by `terminalRowKey`, then one `RailSessionRow` per session id, each reading only its own row through `list.view(sessionId)`, so a status or title change re-renders that row alone. Terminals come from `useTerminals()` (`src/terminal`) for every placement of the project, retained while the project is listed; a click opens the terminal's pane, and its close ends the PTY. A project opens when it has terminals, as today.
- **Session rows** are a read-only projection of `useSessionStores().list`: the project tree groups `list.order()` (the visible rows' refs, which change only when a row joins, leaves or moves) by `ref.projectId` (`sessionIdsByProject`); archived rows and subagents never show (subagents are panel tabs). The session list store owns rows, order (`human_turn_desc`) and status; the rail never fetches, orders or patches them.
- **Views** (`SessionsHeading`): the heading names the view and holds the session options menu: "Sessions by" Projects or Activity (`preferences.sidebar.view`), "Show settled" (`preferences.sidebar.showSettled`, which shows settled rows in both views) and "Hide working statuses" (`preferences.sidebar.hideWorkingStatus`). The Activity view (`ActivityView`) is `list.activityOrder()`: one flat list of every session the reader may read, across projects, each row captioned with its project's name, with "Load more" for the store's next page.
- **Activity filter** (`activityFilterTransition` in `sessions-heading.tsx`): while working statuses are hidden, a button in the Activity heading cycles All → Working → Needs you, and the heading names the filter. The filter in force is derived: it is All whenever working statuses are shown, and showing them resets the cycle, so hiding them again starts at All. It filters the loaded rows with `matchesActivityFilter` from `src/session` (Working: pending, running or in background; Needs you: waiting on the reader, interrupted, or an unseen finished or failed result).
- **Hidden working statuses**: the sidebar carries `data-hide-working-status`, and while it is on a row's working and background marks are hidden and still until the row is hovered or focused; the glyph keeps its place, so nothing moves.
- **Title marquee** (`SessionTitle` in `session-row.tsx`): a hovered title that overflows scrolls to its end; it is measured only on hover, and reduced motion keeps the ellipsis.
- **Keyboard**: the up and down arrows move focus between session rows (`moveRowFocus`); a row is one tab stop until it is engaged.
- **Paging**: a project shows 5 rows, and "Load more" shows 5 more, asking the store for its next page when the loaded rows run out. The store pages the whole list, so there is no per-project total.
- **Selection**: the active project, session and terminal rows are the ones the focused pane shows (`workbench.selectors.shownContent()`), while the route names a workspace. During a switch the pane keeps the previous session until the next one is laid out, and the rail changes with it in the same frame.
- **Navigation status** (`model.ts`): `permission` (the session waits on you) and `error` (a failed turn you have not seen) draw a blue dot, `done` (a finished turn you have not seen, and a terminal whose agent ran since you last looked) a grey dot, `interrupted` (a turn lost on runtime restart) a still blue attention dot, `working` (also pending and retrying) a ring spinner, `background` (a session running in background, per `sessionActivity` from `src/session`) a still ring around a dot that pulses, and `idle` nothing, in the glyph column before the title. A session's unseen outcome is derived from its row (`unseenOutcome` from `src/session`: its last turn ended after the reader's seen mark, and it is not running, waiting or working in background); a finished or failed session you have seen, and a cancelled turn, draw nothing.
- **Age**: `createdAt` as a compact age ("<1m", "2h", "3d"), refreshed by the app's one age clock (`useAgeClock()` from `src/lib/clock.tsx`) at the instant the label's text changes and never while the page is hidden; the palette's session ages and the accounts' checked ages read the same clock.
- **Engagement** (`hover-engagement.ts`): a row's Settle button and a project header's actions mount only while the pointer or keyboard is on them, so the accessibility tree holds one "New Session" button and one Settle button at a time. With a coarse pointer a row's Settle button is always shown beside its age, with the 44 px hit area of `src/ui/touch.css`.
- **Compact tabs** (`CompactSwitcher`, `switcher-items.ts`): today's strip in the workbench header while the sidebar is unpinned. One tab per alive workbench content in insertion order (sessions, drafts, terminals, plugin panes; files are panel tabs), titled by its pane kind, with the project's outline avatar (or the ring spinner while working, the background mark while it runs in background, a corner dot when it needs you), a hover card (title, project · workspace, status), a close button and middle-click close. A click shows that content at once; the active tab scrolls into view. Holding ⌘ for 500 ms shows each tab's `claxedo.surface.N` keybind when such a command is registered.
- **Account card** (`account-card.tsx`): today's card and menu over `useAuth()`. Signed in, it shows the avatar and name; while signing in, a spinner and "Signing in…"; while a signed desktop account's name is still being looked up, a spinner beside "Signed in"; otherwise "Sign in" when `useAuth().offered(capabilities.signedIn)` says the binding can sign in (the web: the server issues sessions; the desktop: a signed-capable build), else today's local "Not signed in" with the monitor mark. The trigger is a sidebar row: it has no fill at rest, only while hovered, focused or open. The menu holds Usage (Settings → Usage), Settings, Help, then Cancel sign in, Sign in or Log out; a failed sign-in or sign-out toasts. Today's organization switch is not ported: the adapter has no route for the user's organizations.
- **Where a session lives** (`sessionMarker`): a row whose placement is a cloud workspace, another machine or a worktree carries today's trailing icon (cloud, server or worktree) named "Cloud environment · {name}", "Another machine · {name}" or "Worktree: {project} / {name} · {path}"; a session in the project's folder on this machine has none.
- **Dragging a row** (session or terminal) onto the workbench opens or splits it there, as today: the row is a `navigation-row` drag source whose content is opened unfocused when the drag starts (`workbench.open(kind, state, false)`); released back over the rail, it just opens.
- **Opening a session** pushes today's URL: `/s/<id>` for a session on this machine's folders and worktrees, `/w/<ws>/session/<id>` for a cloud or another machine's workspace, so Back returns.
- **Row actions** (`createSessionActions`, `createRowNavigation`, shared by both views): Settle on hover, or "Return to active" on a settled row shown under Show settled (`list.settle`; the row's `settled` and `canSettle` come from `src/session`), and a context menu (right-click or double-click) with Copy session link, Rename and Settle or Return. A settled row leaves both views at once unless Show settled is on. Archive and Delete are not row actions; an agent deletes a session with `session_delete`. Their outcome reaches the row through the session list store.
