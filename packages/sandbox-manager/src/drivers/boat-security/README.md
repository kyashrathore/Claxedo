# Boat native harness container policy

`boatContainerSecurity` owns the staged policy files, Docker security arguments and a SHA-256 identity over both. Boat writes the files through its file API before startup. After Docker is ready, the startup command loads the AppArmor profile if the host reports AppArmor, then creates the runtime with the reviewed arguments. Failed delivery, security discovery or profile loading prevents startup. There is no unconfined retry.

The seccomp profile and AppArmor policy originate in OpenAI's Apache-2.0 licensed [codex-security](https://github.com/openai/codex-security/tree/1fb0e5fbf8684c926cac2a36d08389b212d28d5a/docker) at commit `1fb0e5fbf8684c926cac2a36d08389b212d28d5a`; the license is retained and included in the published package. The seccomp content is unchanged. AppArmor is represented as JSON lines for portable bundling, and its profile and peer name are changed to `claxedo-workspace-runtime`. Both retain their upstream syscall, proc, sysfs and kernel restrictions while allowing Bubblewrap's nested user/mount namespaces.

The runtime image runs as UID 0. Mapping parent UID 0 requires `CAP_SETFCAP` since Linux 5.12 ([Linux manual](https://man7.org/linux/man-pages/man7/user_namespaces.7.html)); the all-capabilities-dropped CI experiment failed while writing `uid_map`. `CHOWN` preserves the existing workspace-root ownership repair before runtime startup. Every other Docker capability is dropped, including `SYS_ADMIN`. `no-new-privileges` prevents gaining privileges through executable file capabilities. Migrating to a nonroot UID would require a separate persisted-file ownership and home migration.

Container reuse requires the policy digest as well as the image, init setting and boot command. A matching older container restored during creation is replaced once. Persistent workspace and runtime-home bind mounts are retained.

Boat uploads the runtime environment as a private staging file owned by the VM user. Before container startup, `sudo install` copies it to a root-owned mode-600 file and removes the upload; the container mounts only that installed file read-only. This lets UID 0 read its own environment without `DAC_OVERRIDE` or world-readable credentials. Installation failure aborts startup. The driver downloads a missing image before inspecting or removing an existing container, so Boat's concurrent restoration during the download is reconciled before replacement, and download failure preserves the old container.

`scripts/check-boat-sandbox-policy.sh` runs the immutable runtime image on Linux and checks the exact effective capabilities, no-new-privileges, active seccomp, unprivileged user namespace creation, refusal of a mount namespace without a new user namespace, workspace-root ownership repair, Codex workspace writes with an outside-workspace write denied, and the real runtime image smoke. Driver tests execute the actual startup shell against a container recorder, including reuse, policy migration, Boat's restoration race and fail-closed AppArmor loading. Live Boat acceptance remains a separate deployment check.
