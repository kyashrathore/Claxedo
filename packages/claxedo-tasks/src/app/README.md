# Tasks app entry

The code the app ships as the bundled first-party plugin `claxedo-tasks` (`index.ts`, built by `claxedo-app/vite.plugin-bundles.ts`). It runs in the app's realm on the desktop and in the sandboxed plugin frame on the web, and reaches the server only through the plugin API: `server.fetch` on the routes its manifest names (`/api/claxedo/tasks`, `/api/claxedo/plugins`), with the kit's own client (`tasks-client.ts` over `client/client.ts`).

## Owned concepts

- **Transcript cards** (`tool-cards.ts`): the five `task_*` tool card templates.
- **Surface sync** (`surface/sync.ts`): every surface here is drawn from a pure frame (`components`, `data`) of the program's state. The sync sends the first frame whole, then only the components whose JSON changed and a patch per changed data path (order-free comparison). Input fields write the data model inside the app and tell the program nothing until an event, so the sync is told what the app holds (`observe`) when an event carries it, and a redraw never overwrites text the person typed. `force` sends a path unchanged, as a Board `move` refusal needs.
- **Settings → Presets** (`presets/`, section `presets`, `/settings/claxedo-tasks%2Fpresets`): a list of the person's presets (archive and restore as a row toggle, a switch for archived ones) and an editor: name, Local or Cloud, instructions, whether agents may start it, the primary configuration and optional planning, implementation and review ones, each an `AgentConfigurationPicker` the app draws, and for Cloud the plugins and skills from the Marketplace catalog (`presets/catalog.ts`). Every editor event carries the whole draft (`/draft`), so the program's draft always matches what the person sees. Save validates (`presets/draft.ts`); a slot's problem shows at the top of its section, and a Cloud preset naming a harness that runs in its own session host is refused with the kit's reason (`cloudPresetHarnessRefusal`) before it is sent. A `stale_revision` refusal keeps the edits, adopts the current revision and asks to save again. A placement the server does not offer shows a warning; saving keeps the choice.
- **Tasks page** (`page/`, page `tasks`, `/tasks/:taskId?`, a tab page with the sidebar row Tasks): one surface for the list and a task's detail, chosen by the route param (`navigated` reloads; a deep link opens the detail directly).
  - The list: tabs Active, Backlog and All tasks; the project (a Combobox over the host's projects, followed when they change), the preset rows start with, List or Board, and under Display the status filter, the date shown, subtasks and grouping by status. Grouped tasks draw as a Board (`list` layout in the List view, `columns` in the Board view). A drag or keyboard move sets the status; a refused move is answered by resending the lanes (`force`). A row's tools start it with that preset or open its session, and move it to the previous or next status, which is how a move is made on touch, where a Board has no drag. Load more pages the list.
  - Create (`page/create-view.ts`, `page/create-commands.ts`): title, description, status, project and up to the kit's maximum of images, picked or dropped or pasted onto the form (`FilePicker` with `paste: "section"`; the app fits each image under the kit's size). A refused image says why; a created task opens.
  - The detail: title and description saved with the task's revision (a `stale_revision` keeps the edits, adopts the current revision and shows the new title), images read through the attachment route as `data:` URLs, subtasks with an inline add, the status, facts, archive or restore (confirmed), and per configuration slot its sessions: Start or Start again with a preset that configures the slot, Continue from the last session, Open session, Send task for a session the task never reached, and the attempts.
  - Start (`page/start-run.ts`, `page/start-commands.ts`): reads the task's links for the next attempt, asks the server's preview, starts, and for a Cloud preset follows the cloud workspace's start (`workspaces.followStart`) and starts again with the same request id; the progress shows as a spinner line, a refusal as a warning, and the session opens (`sessions.open`).
- **Paging** (`paging.ts`): every page of a cursor list; both surfaces read all presets through it.
- **Words** (`dictionary.ts`, `words/`): the plugin's `en` dictionary, merged from the card, common, preset and page words.

## State

`page/state.ts`: the route (list or a task), the task list (`idle`, `loading`, `ready` with its cursor and the next page's `idle`, `loading` or `failed`, `failed`), the presets, the create form (closed or open with its images, refusals, `creating` and problem), the detail (`loading`, `ready`, `missing`, `failed`, with its edits, revision, `saving`, conflict and error), the start progress (`page/start-run.ts`: `idle`, `preparing`, `starting`, `machine` with the cloud step) and the start refusal. `page/page-model.ts` applies partial patches to the latest state, as Presets does.

`presets/state.ts`: the list (`loading`, `ready`, `failed`), the catalog (`idle`, `loading`, `ready`, `failed`) and the editor (`closed`, or `open` with its draft, problems, `saving`, refusal and whether it changed elsewhere). The program changes state only by partial patches applied to the latest state, so an answer that lands late never restores an older one.

## Flows

63 Settings → Presets (`e2e/flows/63-tasks-presets.spec.ts`) and the Tasks page: create with a picked and a pasted image, board moves by drag and keyboard, an edit through a conflict, a subtask and a local Start (`e2e/flows/63-tasks-board.spec.ts`), web and phone. 12 opens Tasks from the sidebar as the page tab; 36 opens a task from its transcript card.
