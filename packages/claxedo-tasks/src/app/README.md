# Tasks app entry

The code the app ships as the bundled first-party plugin `claxedo-tasks` (`index.ts`, built by `claxedo-app/vite.plugin-bundles.ts`). It runs in the app's realm on the desktop and in the sandboxed plugin frame on the web, and reaches the server only through the plugin API: `server.fetch` on the routes its manifest names (`/api/claxedo/tasks`, `/api/claxedo/plugins`), with the kit's own client (`tasks-client.ts` over `client/client.ts`).

## Owned concepts

- **Transcript cards** (`tool-cards.ts`): the five `task_*` tool card templates.
- **Surface sync** (`surface/sync.ts`): every surface here is drawn from a pure frame (`components`, `data`) of the program's state. The sync sends the first frame whole, then only the components whose JSON changed and a patch per changed data path (order-free comparison). Input fields write the data model inside the app and tell the program nothing until an event, so the sync is told what the app holds (`observe`) when an event carries it, and a redraw never overwrites text the person typed. `force` sends a path unchanged, as a Board `move` refusal needs.
- **Settings → Presets** (`presets/`, section `presets`, `/settings/claxedo-tasks%2Fpresets`): a Header (Your presets, New preset) over a list of the person's presets, each row opening its editor with a click and archiving or restoring with its icon-only toggle (`archive`, `refresh`), with a switch for archived ones; and an editor of plain sections: name, Local or Cloud, Instructions (a RichTextEditor, Mod+S saves), whether agents may start it, the primary configuration and optional planning, implementation and review ones, each an `AgentConfigurationPicker` the app draws, and for Cloud the plugins and skills from the Marketplace catalog (`presets/catalog.ts`). Every editor event carries the whole draft (`/draft`), so the program's draft always matches what the person sees. Save validates (`presets/draft.ts`); a slot's problem shows at the top of its section, and a Cloud preset naming a harness that runs in its own session host is refused with the kit's reason (`cloudPresetHarnessRefusal`) before it is sent. A `stale_revision` refusal keeps the edits, adopts the current revision and asks to save again. A placement the server does not offer shows a warning; saving keeps the choice.
- **Tasks page** (`page/`, page `tasks`, `/tasks/:taskId?`, a tab page with the sidebar row Tasks): one surface for the list and a task's detail, chosen by the route param (`navigated` reloads; a deep link opens the detail directly).
  - The list: a Header titled Tasks with the project as a menu chip beside it (the host's projects, followed when they change) and, on the right, the List or Board toggle (icon-only chips) and New task; under it the tabs Active, Backlog and All tasks. Tasks always draw grouped by status as a Board: `list` layout in the List view, `columns` in the Board view, each group with an icon-only New task in that status. A row (`page/row-items.ts`) is one click target that opens the task: its status chip (an icon-only menu that sets the status), its key in monospace, its title, then its facts (the parent's key for a subtask, subtasks done, sessions, the update age) and, on hover or always on touch, its tools: Start with the last-used preset (the first active one before any start) or open its session, and archive (confirmed) or restore. A drag or keyboard move sets the status; a refused move is answered by resending the lanes (`force`). The status chip is how a card moves on touch, where a Board has no drag. Load more pages the list.
  - Create (`page/create-view.ts`, `page/create-commands.ts`): a Dialog opened by New task (status To do) or a group's New task (that status): a breadcrumb "Project › New task", a borderless title (Enter creates), a RichTextEditor description ("Press '/' for commands", Mod+Enter creates), the attached images as 64 px thumbnails with a remove on hover, a bar of chips (Status: Backlog or To do, Project) and an attach button (a FilePicker `button` taking pastes and drops anywhere in the dialog; the app fits each image under the kit's size), then Cancel and Create task. Escape, the close button or Cancel drop the draft. A missing title or project, or a refused image, says why in a notice above the bar; a created task opens.
  - The detail (`page/detail-view.ts`): a breadcrumb (Tasks, then "Project › KEY"), and a sidebar Grid: the borderless title over the description editor, the images, the subtasks (rows like the list's, with an inline "Add subtask…" field) and the sessions; on the right (under the title on a phone) the properties, a KeyValue whose Status is a menu chip, with the project, the parent (a link) for a subtask, the preset it started with, the session that created it, the dates, and Archive or Restore (confirmed). The title and description send `taskEdited` as they settle, so a sticky Save and Discard bar shows only while they differ from the task; Enter in the title, Mod+S and Mod+Enter in the description save. A save goes with the task's revision; a `stale_revision` keeps the edits, adopts the current revision and shows the new title. Images are read through the attachment route as `data:` URLs. Sessions are one row per configuration slot with its preset chip and Start (Start again, Continue from the last session) or Open session, a notice for a session the task never reached (Send task), and the attempts.
  - Start (`page/start-run.ts`, `page/start-commands.ts`): reads the task's links for the next attempt, asks the server's preview, starts, and for a Cloud preset follows the cloud workspace's start (`workspaces.followStart`) and starts again with the same request id; the progress shows as a spinner line, a refusal as a warning, and the session opens (`sessions.open`).
- **Paging** (`paging.ts`): every page of a cursor list; both surfaces read all presets through it.
- **Words** (`dictionary.ts`, `words/`): the plugin's `en` dictionary, merged from the card, common, preset and page words.

## State

`page/state.ts`: the route (list or a task), the project chosen, the collection and the view, the task list (`idle`, `loading`, `ready` with its cursor and the next page's `idle`, `loading` or `failed`, `failed`), the presets, the preset rows start with (the last one a start used), the create dialog (closed or open with its status, images, refusals, `creating` and problem), the detail (`loading`, `ready`, `missing`, `failed`, with its edits as last settled, revision, `saving`, conflict and error), the start progress (`page/start-run.ts`: `idle`, `preparing`, `starting`, `machine` with the cloud step) and the start refusal. `page/page-model.ts` applies partial patches to the latest state, as Presets does.

`presets/state.ts`: the list (`loading`, `ready`, `failed`), the catalog (`idle`, `loading`, `ready`, `failed`) and the editor (`closed`, or `open` with its draft, problems, `saving`, refusal and whether it changed elsewhere). The program changes state only by partial patches applied to the latest state, so an answer that lands late never restores an older one.

## Flows

63 Settings → Presets (`e2e/flows/63-tasks-presets.spec.ts`) and the Tasks page: a New task dialog that Escape closes with focus back on New task, create with a picked and a pasted image and Enter in the title, board moves by drag (web), the status chip (phone) and keyboard, a card opened with a click, an edit through a conflict, a subtask added with Enter and a local Start (`e2e/flows/63-tasks-board.spec.ts`), web and phone. 18 (`e2e/flows/18-task-create.spec.ts`) creates a task in the dialog: its parts in order (breadcrumb, title, description, status chip, Create task), a status from the chip's menu, a description written as rich text ("## Plan"), an image kept after another is removed, all three read back. 12 opens Tasks from the sidebar as the page tab; 36 opens a task from its transcript card.
