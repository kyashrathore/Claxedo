# Cursor profile

The pinned Cursor SDK locates its configuration through `os.homedir()`: `~/.cursor/mcp.json`, `settings.json`, `sandbox.json`, `hooks.json`, `rules`, `skills`, `skills-cursor`, `agents`, one plugin per child of `~/.cursor/plugins/local` (manifest at `.cursor-plugin/plugin.json` or `.claude-plugin/plugin.json`, skills under `skills/*/SKILL.md`, MCP servers in `mcp.json` or `.mcp.json`), its agent store under `~/.cursor/projects`, and a `~/.cursor/.gitignore` it writes itself. It has no configuration-directory option; `CURSOR_DATA_DIR` moves only the `projects` config resolver, not the agent store. Source: `@cursor/sdk@1.0.24` `dist/esm/357.js` (`loadUserLocalPlugins`, `ensureCursorDirGitignore`, `CURSOR_DATA_DIR`), `sqlite.js` (`import { homedir as i } from "node:os"`), `options.d.ts` (`LocalAgentOptions.settingSources`).

So the SDK never runs against the person's own home. This profile composes a Claxedo-owned home per (session owner, credential binding, plugin selection): the machine owner's own `~/.cursor` is mirrored read-only into `<home>/.cursor` at every session start (`mcp.json`, `settings.json`, `sandbox.json`, `hooks.json`, `rules`, `skills`, `skills-cursor`, `agents`, and the person's own `plugins/local` entries), each file replaced atomically through the shared `profiles/config-mirror.ts` (links checked against the person's `.cursor` root, a skill directory linked from outside it accepted when it holds `SKILL.md`, secret-looking files left out), the same mirror the Claude and Codex profiles use. A session owned by anyone else gets an empty configuration. Projected plugin roots are copied into `<home>/.cursor/plugins/local` under marker-owned names (`claxedo--<root>--<instance hash>`, marker `.claxedo-agent-plugin.json`), replacing the previous managed set transactionally; a link inside a root that resolves outside it fails the copy. The SDK reads the mirrored `mcp.json`, rules, skills, hooks and settings only through its `user` setting source, and the plugin folder only through `plugins`, so the profile returns `settingSources: ["user"]` for every home and adds `"plugins"` when a root was delivered. The SDK's own state (`projects`, `worktrees`, `plugins/cache`, `.gitignore`) lands in the Claxedo home.

The SDK accepts stdio, HTTP and SSE MCP servers in `Agent.create` and `Agent.send`. The profile passes projected servers and the first-party local MCP server by name, rejecting duplicate names. Source: the pinned SDK's `McpServerConfig` and `AgentOptions`/`SendOptions` in `dist/esm/options.d.ts`.
