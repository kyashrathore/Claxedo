# Cursor SDK transport

The pinned SDK reads `CURSOR_BACKEND_URL` as its module loads, locates every configuration and state file through `os.homedir()`, and exposes no option for either. Neither can be changed from inside a `worker_threads` worker: Node keeps `os.homedir()` on the process's real `HOME`, and Bun ignores a worker's `env.HOME` and keeps the SDK's namespace and named `node:os` imports on the real home. So this transport runs the SDK in one child process per (credential binding, Claxedo home), started through `services.spawn` with `CURSOR_BACKEND_URL` and `HOME` in its environment, and speaks the `protocol.ts` commands over NDJSON on stdin/stdout through the shared `NdjsonOwnedProcess` and `PendingRpcRequests`. The host keeps stdout for protocol frames and sends the SDK's own console output to stderr. An SDK run error fails only its own turn. A host crash, an invalid frame or an expired command fails every pending call on that host; the next turn starts a new host for the key and resumes its agent. A run the dead host was driving stays `running` in the SDK's agent store under the Claxedo home, and the SDK refuses every later send to that agent (`already has active run`), so a host resuming an agent the SDK reports as running first ends that agent's running runs with `Agent.cancelRun`. A host resumes an agent only when it holds no live run for the session, and turns on a session never overlap, so the run it ends has no host left. A host is retired when its last session closes. The transport never locates the host script: its composer passes the command in `worker`. In source and in the package's dist the script is the export `@claxedo/harness/cursor-worker`. A product that inlines this transport into its own bundle ships `CURSOR_WORKER_FILE` beside that bundle, built by `scripts/cursor-worker.ts` with every npm package left external, and stages those packages where Node resolves them from the worker, because `@cursor/sdk` loads lazy chunks relative to itself and cannot be rebundled.

The home comes from the Cursor profile, keyed by the session owner, the binding and the plugin selection; the host key combines the binding with that home, so sessions of one owner on one binding with one plugin selection share a host and sessions that differ in any of the three do not. A projection change on a live session updates the plugin folder of its current home in place, so the agent store the SDK keeps under that home stays resumable.

`CursorEntryLifecycle` serializes host refresh, configuration and close for each attached entry. Closing blocks new entry operations immediately. An acquisition already in flight releases its host when it completes after close begins; close releases the entry's remaining reference. Concurrent closes share the same completion.

An error the SDK throws from `Agent.create`, `Agent.resume` or `send` crosses the host protocol with its class name, code and `isRetryable`, and becomes an `sdk` `TransportError` that keeps that retryability and carries `{ sdkError, code }` as its detail (`errors.ts`). A run Cursor ends in error is the harness's own outcome: the turn gets its `error` event and the stream ends, with nothing thrown. A stop sends the SDK's `Run.cancel()` through the host and reports the run terminal once the turn's stream has ended within the stop's deadline; a run still going at the deadline is unknown, with a `cancellation_timeout` error.

The SDK cancels only a whole run: it has no call that stops one Task subagent, so this transport does not implement `backgroundTasks`. A Task that moves to the background completes its tool call at that moment (`isBackground`), and the SDK reports nothing when the subagent later ends, so the transport cannot report background work or settle that subagent's row.

`CursorRunState` owns the SDK run until terminal observation and any outstanding cancellation settle. A cancellation during send waits for the SDK handle; concurrent callers share one cancellation outcome. If the SDK rejects cancellation, each caller receives the error and a later explicit cancel can use the retained handle. Cancellation failure does not stop stream observation or acknowledge a successful stop.

Claxedo ships the SDK as a library, pinned exactly in `package.json` (1.0.32) together with its platform package (`@cursor/sdk-<platform>`, `rg` and `cursorsandbox`), which the SDK's own `optionalDependencies` pin to the same version. The person installs nothing, and the SDK starts no Cursor program of theirs: it runs Cursor's agent loop inside the host and calls Cursor's backend over Connect-RPC, naming its version in `x-cursor-client-version`. So this transport declares no `HarnessVersionRange` and has no entry in `flows:versions`: there is one version, the pin, and the conformance suite and the `H1.cursor` flow run it against the scripted backend built from that pin's own descriptors. The only skew is between the pin and Cursor's backend, which Claxedo cannot read before a run. A backend refusal reaches the turn as the SDK's typed error; an interaction update or tool case the pin's protobuf does not know decodes without a case and the SDK drops it before `Run.stream()`. Of the 69 tool cases 1.0.32's protobuf knows, its converter passes 15 (`shell`, `delete`, `glob`, `grep`, `read`, `edit`, `ls`, `readLints`, `mcp`, `generateImage`, `recordScreen`, `semSearch`, `createPlan`, `updateTodos`, `task`) and drops the rest, web search and fetch, ask-question and computer use among them, so those never reach Claxedo. A bump moves the pin to the newest release older than the install's three-day release-age gate, and `e2e/harness/cursor/descriptors.test.ts` then holds the credential broker's Cursor row to the new pin's methods.

The host receives a broker-signed placeholder for a bound account. The egress broker exchanges the real key, keeps the real access token, and returns that signed placeholder in the exchange reply; subsequent Connect calls are substituted inside the broker. In a cloud sandbox the bound account is a provider-edge placeholder instead: the edge writes the real key only on the `POST /auth/exchange_user_api_key` request, and the SDK sends the access token Cursor returns on every later call itself, so that token is in the sandbox and the key never is. With no product binding, only a machine-owner local session can use the machine's explicit `CURSOR_BACKEND_URL` and `CURSOR_API_KEY`.

The native SDK carries run status, usage and tools through `Agent.create` and `Agent.send`. ACP does not expose these SDK calls. The transport's translator is `translate/adapter.ts`; the SDK owns its own loop and tools.

`Run.stream()` frames are mapped or ignored by name; the shapes come from 1.0.32's converter and are recorded against the scripted backend in `src/translate/corpus/cursor-sdk/sdk-1.0.32-*.json`. Each `assistant` and `thinking` frame carries one delta, never a snapshot, and every one reaches the reply; a `thinking` frame with empty text only reports the thought's duration, which the projection measures itself. A `tool_call` frame is its tool's row. An MCP call arrives named `mcp` and is named `mcp__<server>__<tool>` from its arguments, so Claxedo's own `create_subagent` binds its child, and a result the MCP server marks `isError` fails the row. `usage` arrives once per turn end inside a run, and the run's usage is their sum; Cursor reports no context window, so the meter stays unknown. `task` carries the summary Cursor writes when it compacts the conversation, a completed `session-compaction`; the proto's summary start and completion (with its failure flag) never leave the SDK, which drops them before `Run.stream()` and `onDelta` alike. `status` frames are progress: `CREATING` and `RUNNING` mark the session busy, and the run ends at the host's result frame from `Run.wait()`, which carries the SDK's `RunError`; its message is the turn's error, and a usage-limit, rate-limit, credential or model code sets the error's class. `user` (the prompt echo), `request` (stored by the SDK, never streamed live) and `system` (never emitted by a local run) produce nothing. A frame type, status or tool status the transport does not know leaves one bounded `debug` diagnostic per kind per run, never the frame. The SDK reports nothing while it waits out a refused request: a run the scripted backend refused with HTTP 429 took 14 s to end in error, with no frame in between, so there is no retry to show.

The host also subscribes to `SendOptions.onDelta`, whose interaction updates include what `Run.stream()` leaves out, and forwards two kinds as `delta` replies (`host-deltas.ts`). A shell's `shell-output-delta` carries no call id, so its stdout and stderr go, as the command's output so far, into the one shell whose `tool_call` is running, as `tool-content`; with none or several running it is dropped with one debug note, because nothing names its shell. A `tool-call-delta` carries a Task subagent's own text, thinking and tool calls under the Task's call id; the host posts it only after the Task's own `tool_call` frame, whose admission creates and binds the child (the Task's transcript is `live`), and the transport translates it on a translator of its own for that child and routes it to the child by the Task's call id. The other updates duplicate `Run.stream()` (text, thinking, tool calls, the prompt echo, turn ends with their usage) or carry nothing a reply can truthfully show: `token-delta` is an output token count in flight, not a request's usage or the context's size, and step starts, step ends and tool-request counts only pace the loop. The SDK drops summary start, summary, and summary completion from `onDelta`, and no update reports a background Task starting or ending.

What this transport carries that ACP does not:

- **Permission modes** are the SDK's `LocalAgentOptions` (`sandboxOptions`, `autoReview`), read when the local agent is created or resumed and enforced by the SDK at the first send. The transport records a selected mode on the session's config and closes the host-side agent, so the next turn resumes the agent with the new options (`appliesFrom: "next-turn"`). With no mode selected it passes no sandbox options, so Cursor's own configured defaults stay in charge, as in today's driver, and reports no current mode. The SDK refuses a sandboxed mode with its own `ConfigurationError` unless it finds a `cursorsandbox` binary at `node_modules/@cursor/sdk-<platform>/bin` or `node_modules/@cursor/february-<platform>/bin` in a directory above the host script or the Node executable. The SDK's own platform package carries one, but in the source layout bun's isolated install keeps that package under `node_modules/.bun`, where the walk never looks.
- **Plugins** reach Cursor through the profile's Claxedo-owned home and `settingSources: ["plugins"]` on the agent.
- **Subagents**: a `Task` tool call is admitted through `TurnBroker.observeSubagent` with a live transcript at its first frame, and its activity streams to the child session (see `onDelta` above). The transcript file Cursor names on success is not registered: it lies under the Claxedo home, outside the root the product's transcript resolver serves.
- **Steering** sends the steered prompt's text (attachments written to the workspace and named on path lines, as in a prompt; images do not travel inline) to the running run's `Run.steer`. The SDK injects it as context and answers once Cursor's backend reports the injection: `complete_delivered` is an accepted steer, and `revert_to_followup` (Cursor queued it for the next turn, cancelled or rejected it, or gave no answer within the SDK's 15 s) is `declined`, so the runtime sends it as a follow-up. The `user` frame Cursor streams where the steer entered carries only its text, never an id, so the transport does not report where it entered, and a steered prompt stays accepted rather than written into the transcript, as with Pi.
- **Titles** are one send on a throwaway local agent in the session's host (`naming.generateTitle`); a local Cursor agent never names itself and the SDK has no rename.
- **Models** come from `Cursor.models.list` in the session's host, with `auto` pinned ahead of the catalog; a draft reads them through a probe host retired afterwards. Through a binding the catalog host is not brokered, and the error names that.
- **Goals** run `/goal <objective>` as a provider turn; the goal snapshot is synthesized around the run (`active`, then `complete`, `paused` or `blocked`), because the SDK reports no goal state of its own. Stop and delete interrupt the run through the SDK's `cancel`.
- **Attachments**: every file is written under the workspace's `.claxedo/attachments` and named on a path line; images also travel inline as SDK images.

Cursor SDK MCP image results use `{ image: { data, mimeType } }`. Provider-local attachment paths require an authorized opaque handle; absent that capability, translation fails closed.

Composing a session or discovery home first records its use through `services.recordHomeUse`, and the SDK host is spawned with that home, so the host keeps it from collection for as long as the host process lives, including after the runtime that launched it has gone. A shared host holds the home for every session it serves.
