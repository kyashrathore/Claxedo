# Pi RPC transport

Pi has no MCP protocol and no ACP wrapper. The native RPC transport carries Pi's session resume, `get_commands`, extension UI dialogs and notices, steering, its own session name, and Claxedo's first-party MCP tools. Source: pinned Pi 0.85.1 `packages/harness/e2e/.artifacts/pi/node_modules/@earendil-works/pi-coding-agent/docs/rpc.md`.

`commands.list` returns every entry of `get_commands`. Pi lists only commands a `prompt` runs: extension commands, prompt templates and skills. Its interactive built-ins, such as `/model` and `/settings`, aren't listed (`docs/extensions.md`, `pi.getCommands()`). The conformance case proves an extension command from its fixture. Pi's bundled `/llama` downloads models, so it can't run in an offline suite.

Pi has no MCP intake, so a person's configured MCP servers stay refused (`profiles/pi`). Claxedo's own server reaches Pi through Claxedo's `claxedo-first-party-mcp.ts` extension, installed under the Claxedo state root beside the title extension and added with `-e` to a harness launch only when `services.firstPartyMcp` returns an entry for the session and its locality; it returns none for a remote session. After launch the transport sends `/claxedo-mcp <entry>` over RPC stdin, never argv or the environment, where Pi's bash tool would expose the bearer; the extension connects over MCP streamable HTTP, registers each tool as `mcp__<server>__<tool>` through `pi.registerTool`, activates it, and closes on `session_shutdown`. The client runs inside Pi's own process, so it is extension source and cannot share the host's in-process client. A failed connection retires the launch and refuses the start. Source: pinned Pi `docs/extensions.md` (`registerTool`, `setActiveTools`, `session_shutdown`).

A draft's catalog probe is kept by `DraftProbeCache` while the files Pi read for it are unchanged: the owner profile's `settings.json`, `auth.json`, `models.json` and `trust.json`, and the workspace's `.pi` folder and `.pi/settings.json` (pinned Pi `docs/settings.md`, `docs/sdk.md`: project settings come from the current directory only). A brokered profile's files are written from the credentials the key already names.

A launch no session owns (a probe, or a start that failed before the session was remembered) whose retirement does not settle never fails the read it served and never touches health; it is retried when its process exits, before every later launch, and at dispose. A session's own refused retirement keeps the session and reads `degraded`. A process lost under a session reads `harness_process_lost` through `ProcessLosses` until a replacement for that session starts or it closes; a deliberate retirement is not a loss.

The transport starts only through `HarnessServices.spawn`. A failed RPC exchange makes that launch unusable; it does not prove the operating system process exited. The owner of the process must retire it and report the result. RPC records split on LF, preserving Unicode line separators inside JSON strings, and a response must match both the pending id and command.

The runtime's old Pi adapter remains the only production path until the atomic P3 cutover. This folder is exercised through the contract conformance suite against pinned Pi and the scripted model server.
