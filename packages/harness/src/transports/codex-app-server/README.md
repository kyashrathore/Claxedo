# Codex app-server transport

This transport uses Codex's JSON-RPC app-server over stdio. It carries native `turn/steer`, `thread/goal/*` goals and provider-started turns, thread recovery, usage, quota windows, and `model/list` discovery. ACP does not expose those native operations. A process belongs to one session and is started only through `services.spawn`; retirement uses the returned owned-process handle. The broker owns request persistence and grants before any answer goes back to Codex. An approval's grant key is the contract's `grantIdentity` digest of its method, workspace directory, permission mode and native parameters without the per-call IDs, so a persisted grant never carries a command or patch.

`turn/steer` sends the steered prompt's Claxedo id as `clientUserMessageId`. Codex opens a `userMessage` item carrying it as `clientId` where the input enters the turn, and the transport yields `input-incorporated` there; the reply acknowledges acceptance only. The id is recorded before the request is sent, because Codex can open the item before the reply arrives.

The app-server never asks this transport to refresh a ChatGPT token. `account/chatgptAuthTokens/refresh` belongs to Codex's external auth mode, which a client enters only by calling `account/login/start` with `chatgptAuthTokens` and then refreshing the tokens itself; this transport never calls `account/login/start`, so an owner's managed login refreshes inside Codex from its own auth file and a brokered account runs on the configured API-key placeholder. The request, like any other unexpected method, is refused with `-32601`; handler failures remain `-32603`.

Permission modes are today's four, `read-only`, `workspace-write` (the default), `untrusted` and `full-access`, each an approval policy and a sandbox applied to `thread/start`, `thread/resume` and every `turn/start`, so a change lands on the next turn. Every thread starts with the `spawn_agent` dynamic tool: an `item/tool/call` for it starts a child thread (`threadSource: "subagent"`) under the parent turn's mode, model and effort, runs one turn on it, and answers Codex with the child's outcome. It reports that outcome to the broker only once the parent turn has taken every event the child streamed before it, because the broker's report ends the child in the host at once while the child's own streamed events wait in the turn's queue. The child's notifications route to the child session for the life of the entry, and an aborted parent turn interrupts the child's turn. A `spawn_agent` request without a `callId` is refused and starts no child: its spawn edge needs the call a transcript part carries. A completed `create_subagent` item from Claxedo's own MCP server binds the host-minted child to its call before the turn ends, as the spawn edge when the turn's own thread made the call and without an edge when a child thread did, because that call lives in the child's transcript, which the parent never draws. Titles come from an ephemeral read-only side thread archived afterwards, and a rename is written back with `thread/name/set`. Attachments are materialized into the workspace through the shared owner in `translate/attachments.ts`, named in the prompt by path, with images also sent as `localImage`; a file part that is not a `data:` URL is undeliverable and rejects the turn from `send`, as the contract requires of a prompt the transport cannot deliver. `thread/tokenUsage/updated` reports the turn stream does not carry, on the session thread after a turn or on a side or child thread, are metered as growth to the session's last turn; a report for a thread this transport never started is a `codex.usage_unbilled` diagnostic.

Stop, pause, and cancel interrupt the turn, wait for its completion event within the deadline, and only then inventory and terminate the background terminals the turn's command events named, through `thread/backgroundTerminals/list` and `thread/backgroundTerminals/terminate`. Codex's `no active turn to interrupt` answer counts as a completed interrupt. The repository pins one Codex, `CODEX_VERSION` in `e2e/harness/config.ts`, which is also the generator's `@openai/codex` dev dependency and the version the flows and every fault fixture run from `e2e/.artifacts/codex`, never from `PATH`; 0.156.1 answers both terminal methods, and 0.133.0 refused them as unknown variants. A completed turn that observed no command execution reports `cleanup: "verified_clear"`: Codex reports every command it starts as an item, so nothing of the turn's is left to clean up. A turn that ran a command reports `verified_clear` once the inventory after termination is empty, and `unknown` with the refusal as its `error` when Codex refuses the inventory or the termination. A goal pause or stop proceeds once the turn is terminal; when the turn ran a command and its cleanup is not verified clear, the transition is preceded by a `harness-notice` (`codex.background_commands_unverified`) through the session broker. Only a turn that cannot be confirmed stopped keeps the goal unchanged.

A cancellation during `turn/start` waits for the native turn ID within the caller's deadline and interrupts that same captured turn. Old completions cannot settle a new turn.

Translation constraints: cumulative usage replaces the previous observation in its native scope; overlapping native totals must not be counted twice. Child thread attribution uses the observed parent binding. Completed item snapshots contribute only content not already delivered by streaming deltas. A reasoning item that streamed contributes nothing at completion, and each later summary section (`summaryPartAdded`) opens after a blank line. A message or reasoning item that directly follows another item of the same kind opens after a blank line, so two items never run together; after a tool or the other kind it needs none, because the projection already starts a new part there. MCP image results preserve the provider's supplied bytes. Every thread item type of the generated protocol has an explicit kind and tool name, so an item never falls through to an empty generic row: a file change is an `apply_patch` row whose metadata lists each file with its kind, move target and diff; a hook prompt shows the injected text; a sleep carries its duration; a native subagent's interaction or interruption names the agent path; a web search takes its query from the action when the item's own query is empty, and its results are the row's output; a dynamic tool call keeps its arguments and its text result; a generated image is an image attachment (inline when small, otherwise the file Codex saved), never base64 text. A declined or failed file change, a failed or unsuccessful dynamic tool call and a refused image generation are errors, as a declined or failed command is. A completion whose input grew since the item started (a web search's query) updates the row's input.

Every projected MCP server, and Claxedo's own for a local session, reaches Codex in the thread's `mcp_servers`. Codex decides how the model sees their tools, and this transport doesn't override it: for a model whose catalog entry supports search, such as `gpt-5.5`, Codex 0.156.1 defers every MCP tool behind its client-executed `tool_search` tool, so the model first calls `tool_search`, receives the matching `mcp__<server>` namespaces in a `tool_search_output`, and then calls a tool in that namespace. A model without search support gets the tools directly.

Profile preparation first records the shared home's use through `services.recordHomeUse`, and the app-server is spawned with that home, so the home stays out of collection for as long as the app-server lives, including after the runtime that launched it has gone.

A failed turn's error class comes from Codex's own `codexErrorInfo`, one table over every value of the pinned protocol plus the two 0.159 adds: a usage limit for `usageLimitExceeded`; a temporary rate limit for `rateLimitExceeded` and an HTTP failure variant that answered 429; a credential failure for `unauthorized` and an HTTP 401 or 403; a model failure for `serverOverloaded` ("Selected model is at capacity") and `flexUnavailable`; a workspace failure for `sandboxError`; a session failure for `threadRollbackFailed`; and `unknown` for the rest, so the app never guesses a recovery from the message text. A failure that names only Codex's generic session error is explained by the last limited rate-limit window, and that window is a plan limit, so it is a usage limit too. The reset sentence of a limited window comes from the shared `translate/rate-limit-reset.ts`, as Claude's does. A turn Codex itself interrupted with an error (0.159's `tooManyDenials`) ends failed with that error; an interrupted turn without one is a stop. A `willRetry` error is a diagnostic only: the runtime event contract has no retrying status, and its `recovering` status would mark the turn inactive in the app.

Codex token counts include cached input within input and reasoning within output; metering separates those categories. Each native thread/turn is a usage scope, with separate model streams after a model change. The first report seeds from `last`; subsequent growth uses lifetime-total differences so a missed report does not lose spend. Repeated totals refresh context without adding usage. An observation outside a turn contributes only growth since the last observed lifetime total. Bounded thread state evicts the least recently reported thread.

A completed command can have null output fields after streaming stdout or after printing nothing. Preserve the streamed buffer or empty output, never the protocol envelope. `declined` means the command never ran; completed/failed command status agrees with zero/nonzero exit status. `systemError` precedes authoritative error/completion frames and cannot terminalize early, so it is a warning notice. A descendant error folded into an ancestor ends the descendant and remains a diagnostic on the ancestor. JSON-RPC `params` is the single boundary into generated protocol types. Realtime media, hooks/reviews and global app surfaces have no classic chat projection.
