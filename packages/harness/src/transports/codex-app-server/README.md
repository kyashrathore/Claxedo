# Codex app-server transport

This transport uses Codex's JSON-RPC app-server over stdio. It carries native `turn/steer`, `thread/goal/*` goals and provider-started turns, thread recovery, usage, quota windows, and `model/list` discovery. ACP does not expose those native operations. A process belongs to one session and is started only through `services.spawn`; retirement uses the returned owned-process handle. The broker owns request persistence and grants before any answer goes back to Codex.

The app-server never asks this transport to refresh a ChatGPT token. `account/chatgptAuthTokens/refresh` belongs to Codex's external auth mode, which a client enters only by calling `account/login/start` with `chatgptAuthTokens` and then refreshing the tokens itself; this transport never calls `account/login/start`, so an owner's managed login refreshes inside Codex from its own auth file and a brokered account runs on the configured API-key placeholder. The request, like any other unexpected method, is refused with `-32601`; handler failures remain `-32603`.

Permission modes are today's four, `read-only`, `workspace-write` (the default), `untrusted` and `full-access`, each an approval policy and a sandbox applied to `thread/start`, `thread/resume` and every `turn/start`, so a change lands on the next turn. Every thread starts with the `spawn_agent` dynamic tool: an `item/tool/call` for it starts a child thread (`threadSource: "subagent"`) under the parent turn's mode, model and effort, runs one turn on it, and answers Codex with the child's outcome. The child's notifications route to the child session for the life of the entry, and an aborted parent turn interrupts the child's turn. Titles come from an ephemeral read-only side thread archived afterwards, and a rename is written back with `thread/name/set`. Attachments are materialized into the workspace through the shared owner in `translate/attachments.ts`, named in the prompt by path, with images also sent as `localImage`. `thread/tokenUsage/updated` reports the turn stream does not carry, on the session thread after a turn or on a side or child thread, are metered as growth to the session's last turn; a report for a thread this transport never started is a `codex.usage_unbilled` diagnostic.

Stop, pause, and cancel interrupt the turn, wait for its completion event within the deadline, and only then try to inventory and terminate the background terminals the turn's command events named. Codex's `no active turn to interrupt` answer counts as a completed interrupt. The pinned Codex 0.133.0 answers `thread/backgroundTerminals/list` and `thread/backgroundTerminals/terminate` with `-32600 unknown variant` (its client method table carries only `thread/backgroundTerminals/clean`; the list and terminate methods appear in a later Codex, 0.156.1 answers them), so a turn that ran a command reports `cleanup: "unknown"` with the refusal as its `error` instead of failing the stop. A turn with no observed command also reports `cleanup: "unknown"`, because the transport never claims a verification it did not read. A goal pause or stop proceeds once the turn is terminal; when the turn ran a command and its cleanup is not verified clear, the transition is preceded by a `harness-notice` (`codex.background_commands_unverified`) through the session broker. Only a turn that cannot be confirmed stopped keeps the goal unchanged.
