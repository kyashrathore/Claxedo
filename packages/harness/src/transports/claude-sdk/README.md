# Claude Agent SDK transport

The native transport carries local plugin folders through the SDK `plugins` option, live `supportedModels()`, `supportedCommands()` and `supportedAgents()` discovery, per query effort, replay confirmed streaming steering, native `/goal` start and stop, and the SDK's per turn usage events. These surfaces are absent from standard ACP. Claude over ACP can receive plugin folders only through its wrapper's version specific `_meta.claudeCode.options` extension.

The SDK's `spawnClaudeCodeProcess` callback returns synchronously. `HarnessServices.spawn` returns a promise. `ClaudeProcess` gives the SDK streams immediately, forwards them to the process once `services.spawn` returns, and delegates retirement to that exact `OwnedProcess`. The callback never starts a process directly.

Brokered credentials are selected in `StartInput` by the session owner. `TurnInput.origin` is not used for credential choice. The Claude Code home for a brokered session is a Claxedo owned directory containing scrubbed copies of supported settings files and read only copies of named user configuration entries. It never mirrors account files. A machine owner session without brokered credentials uses their own Claude login.

Session config has one owner, the runtime (`configOwner: "runtime"`, as Codex, Cursor, Pi and OpenCode declare). Every launch reads the model, permission mode and permission state from `SessionBroker.config()`; the transport keeps no copy, `config.read` returns the runtime's config, and `config.update` and `setPermissionMode` validate the request and return the config the runtime persists. `StartInput.config` is used only for the draft launch context and probe keys.

A model answer is kept while the files the CLI reads for it are unchanged: the owner's settings files and `.credentials.json` under the config folder, the project's `.claude/settings.json` and `.claude/settings.local.json`, and the `.claude.json` account (on macOS the login itself is in the Keychain, and `.claude.json` is what changes with it). The SDK reads `.claude.json` from `CLAUDE_CONFIG_DIR` when that is set and from the home directory otherwise, which is the folder above the default config folder (`sdk.mjs`, `CLAUDE_CONFIG_DIR ?? homedir()`).

Permission requests are answered by `TurnBroker`; the broker persists an answer before the callback releases the tool. "Always allow" keys the broker grant by the contract's `grantIdentity` digest of the request identity (tool, tool input, workspace directory, permission mode and permission context) together with the SDK `suggestions` rewritten to `destination: "session"`, and returns those suggestions as `updatedPermissions`, so Claude applies them for the rest of the query and never writes the person's settings. On the next launch the transport reads its own grants back from `permissionState.brokerGrants` through `connectionGrantKeys` and folds the saved rules and directories into `settings.permissions` and `additionalDirectories`, so Claude does not ask again. A saved `setMode` is not replayed at launch: the runtime owns the session's permission mode and its ceiling, and the transport has no config write. Within the answered query the SDK applies it, so the transport reports it through `StartInput.permissionModeKept`, and the runtime stores it and publishes the row; the next query starts in the stored mode. A prompt forced by the person's own ask rule (`matchedAskRule`) gets no grant. `decisionReason` is not a grant blocker: Claude Code 2.1.283 sets it to "This command requires approval" on ordinary Bash prompts. The grant identity leaves out only what cannot change the request: the callback's IDs and abort signal, the prompt's display labels (`title`, `displayName`, `description`), and Bash's `description` input, which the tool schema documents as a display summary of the command. Every other tool's input is kept whole, because an MCP or agent tool's `description` can be the content being approved. Blocked path, agent, decision reason and any permission-context field the SDK adds later are part of the identity. The key holds only the digest and the suggestions, because it is persisted in `permissionState.brokerGrants` and published with auto-answers: a Write grant must not carry the file it wrote. A Bash prompt without suggestions uses the same identity.

The command deny floor is a Claude setting the Claude profile ships in `settings.permissions.deny`; Claude Code enforces deny rules in every permission mode, including `bypassPermissions` and `dontAsk` (conformance proves each mode against the real CLI), so `canUseTool` and the broker never repeat it. A rule denial reaches the person as the SDK's `permission_denied` system message, translated to a `tool-error` event.

Every query passes `--thinking-display summarized`. In stream-json mode Claude Code 2.1.284 otherwise leaves the API's default display, which is `omitted` on current Opus and Sonnet models: thinking blocks arrive with empty text and nothing reaches the transcript. The flag leaves the thinking type to Claude Code, which picks adaptive or budgeted thinking per model; the SDK's `thinking` option would force `--thinking adaptive` on every model. Conformance reads the display from the request the real CLI sends to the scripted model server.

The SDK reports `session_id` after a query has begun. The transport immediately calls `SessionBroker.rebind`, which moves the live turn. The process's first reported identity is durable before that turn can finish or crash.

Native goals use `SessionBroker.admitProviderTurn`, and Stop aborts and drains that turn before reopening the native session with `/goal clear`. The clear result must report a successful zero turn command. A goal run wires the admitted turn's signal to its query, so a runtime cancel ends the query, and the transport's own abort ends the run as a cancellation rather than a failure; a cancellation reports terminal execution only when admission settled cancelled or completed. A stop that retired Claude's process reports cleanup `unknown`, never `owned`: an emptied process group does not prove a descendant that called `setsid` is gone, and nothing the transport started is known to be running. A stream that ends without an SDK result fails with the one protocol error in `errors.ts` unless explicitly aborted. Goal progress is read from SDK `active_goal` messages and `goal_status` transcript entries; the mirror answers `load` with null so resume uses Claude's own transcript. The transport reports `actions: []` because Claude has no native pause or resume command. Per turn usage is yielded from the existing Claude translator; mirrored subagent usage is attributed to the session owner through `SessionBroker.meter`. The SDK hands its transcript mirror over as soon as it reads it, ahead of the messages it has yet to deliver, so usage mirrored during a turn is held until the turn reaches its result and is then metered after the stream's own usage; usage mirrored after the result is metered at once.

Translation constraints: Bash reports a nonzero exit in result text rather than a numeric field. Tool images require a base64 source with a media type. Streamed text and a cumulative message snapshot represent one message, so only the unseen suffix is appended. Structured `tool_use_result` has no call ID and can be attributed only when exactly one result block exists. Nested Agent activity belongs to its first-level child. Request answer metadata is present only for completed question calls.

Translation preserves these wire constraints:

- Assistant snapshots repeat streamed text. Each message contributes only its unprojected suffix or the portion beyond the common prefix; a divergent snapshot cannot duplicate the whole reply. Partial tool JSON can update display, but only a complete parse becomes the block's authoritative input.
- `create_subagent` binds a child only when its result belongs to a call the ledger observed. Structured `tool_use_result` has no call ID and can stand in for block content only for a single-result message. Nested Agent calls route through their first-level ancestor. A completed question carries answers in metadata; refusal is an error.
- `task_started` distinguishes Task subagents from ambient chores. Later task-ID-only frames use that recorded classification, and `spawn_depth` identifies nested work even when pinned SDK types omit it. Background-task set replacement may settle known rows but cannot invent spawn edges. A task's call is a spawn edge only when the parent's own assistant message made it as an Agent or `create_subagent` call; a Skill call's forked execution, or a call a subagent made, still routes its frames and joins its observations into one row, with no edge, because the parent's transcript has no part for it. Disappearance proves interruption, not success. A `forked` result is final; only `async_launched` remains running. Task notifications can precede the tool's actual stdout/error result and must not replace it with an empty summary.
- Usage reports for one request are monotonic across stream, assistant and transcript deliveries. The model stream is fixed by the first report; requests accumulate separately by owner and model. Result usage repeats stream accounting and is not added again. Context occupancy comes from the last main-thread request, not a mirrored child's context. Post-turn summaries do not repeat an already projected turn.
- Native titles arrive through transcript `ai-title` or `custom-title` entries, not SDK messages. Rate-limit reset values arrive in seconds and are normalized to milliseconds.
- Bash errors carry the exit code in result text (`Exit code N`), even when the SDK error flag is absent. Tool images preserve supplied base64 bytes; a filename is only a display hint. URL-only image sources provide no MIME type for safe mapping.
