# Embedded OpenCode engine

One `OpenCodeHost` owns the embedded SDK engine and its SQLite writer for all local workspaces in a runtime. The absolute database path is required because the SDK otherwise defaults to an in-memory database and loses sessions on restart. Concurrent first use shares one boot promise; closing waits for a boot already in progress so a late writer cannot remain after shutdown. A failed boot reports an unavailable reason and may be retried on the same engine path. A closed owner is terminal.

The SDK remains behind first use so shell hydration and generic runtime imports do not load its native module graph. The engine uses ripgrep for file search: its alternative indexer walked and hashed this monorepo in background workers, measured at 7 GB of reads and 200% CPU. The SDK's plugin registration settles asynchronously per location, so catalog and plugin-backed workspace reads await that location's activation. The desktop runs the same engine in Node/Electron; no Bun sidecar is involved.

Lifecycle and event health are separate. A host can serve sessions while its stream is reconnecting; collapsing them would hide a working session with a stale UI. The lifecycle progresses from cold through migration and ready to draining and closed. A failed pre-serving attempt is observable as unavailable, while a host already serving work drains instead of switching to unavailable.

The host retains one event pump. Browser subscribers receive its fan-out through the runtime hub, so a tab disconnect does not end another workspace's stream. The pump's `ready()` resolves once its first read is outstanding, allowing a mutation to subscribe before its own first event. A stop refuses further dispatch immediately, then waits for the outstanding SDK read and iterator cleanup. Runtime shutdown refuses events before closing the host, and awaits the drain even if host close fails. A listener that unsubscribes during dispatch cannot skip another listener because dispatch iterates a copy.

Event delivery is at least once after consumer acceptance. Events with both `durable.aggregateID` and `durable.seq` have an ordered per-aggregate position for checkpoints and downstream idempotency. Other events, including text deltas and usage updates, may be lost, duplicated or reordered during reconnect. They are invalidation hints: consumers re-read a snapshot rather than accumulate their payloads. In particular, turn usage closes by comparing the engine's session total before and after the turn, with a deadline, because step events can be missed. Recorded step usage keeps its durable identity. A failed total read yields a diagnostic without holding the turn. Consumers must be cheap and must not throw; a throwing consumer degrades health and is logged without killing the only pump. Stream loss degrades health and reconnects; a waiting turn asks the SDK for completion, then reads the authoritative session outcome. A broker abort interrupts the engine once, because the engine would otherwise keep running the prompt and billing it, then waits a bounded 5 s for the session to go idle and reads the outcome. The snapshot's outcome is mapped by the same translator as the terminal event, so a failed outcome is the harness's own error event in one shape; after the transport's own abort an `interrupted` outcome ends the turn as `cancelled`, because the engine also reports `interrupted` when it stops a turn itself, as it does after a denied permission, and only the abort is the person's stop. A snapshot without a terminal outcome is never turned into an `error` event: after an abort the turn ends with no event, and after stream loss it throws, because the contract reserves `error` events for the harness's reported outcome. A turn's variant is the resolved `turn.effort`, never the stored session config, which the host has already folded into that value.

The catalog port fails on an unavailable engine rather than fabricating an empty list that the UI would treat as a real empty workspace. A config options preview marks the model supplied by the caller as the select's current value so the contract can derive `resolvedModel`. The host supplies the current runtime-owned session model, or an explicitly requested preview model; draft previews use `draft.model`. An omitted model never resurrects the attachment's older config. Session config patches use the shared `applySessionConfigUpdate` contract. Its model list describes what the running host can execute, including effort variants and pricing tiers; The provider catalog operation, which only the workspace owner reaches and which never makes its caller the engine's owner, lists every integration the engine discovers, whether its provider is active, and the models it runs; Settings reads its connection rows from it. Location-scoped SDK lists return `{ location, data }`, so the port reads `data` explicitly.

`WorkspaceScope` is minted only after route authorization and resolves the real directory. The pinned SDK does not authorize `sessions.get({ sessionID })` by location; every session mutation and reply proves the session's location against the caller's scope. A scope is revalidated against the filesystem so symlink retargeting cannot widen access. Session listing passes a flat `directory`: a nested location filter is ignored by the SDK and can expose every workspace. Form answers remain structured values. Pending interaction reads before a serving host is ready return empty without booting the engine.

The session port uses the SDK's flat prompt shape, with model selection coming from agent/config. Its admitted message is read from the SDK response. Revert operations are not exposed: nothing in production stages or clears a revert, and the plan deletes revert. Usage token categories are disjoint: input excludes cache reads and writes, output excludes reasoning, and an engine zero cannot distinguish unreported usage from reported zero. Session paging carries both previous and next cursors. File, agent and skill mentions use their SDK-specific keys; combining agent and skill keys in one computed property loses required-field typing. Assistant content remains opaque until transcript projection, while a session row is projected field by field so SDK shape drift cannot be silenced by a whole-row assertion.

Workspace launch policy projects Claxedo's MCP servers and skill directories into the SDK plugin registries, not project or global config files. Reload reruns transforms against the current document. Plugin storage is keyed by the engine's real directory. A failed write is reported to its caller and does not acknowledge a stale catalog. Skills come from `SKILL.md` in each catalog-approved skill directory carried by the launch document; the schema mints its branded identifiers. There is no directory enumeration. Read and decode failures for an approved skill propagate, leaving the previously installed document intact.

The provider policy persists each workspace's disabled provider IDs in plugin storage and applies activation in the engine catalog, not only in the picker. Invalid stored data is corruption and must fail instead of re-enabling providers. Activation is the SDK's availability switch and survives later provider declarations. Provider definitions declare integrations, endpoint, metadata headers and models; a credential never travels as a definition header. Provider bindings carry broker placeholders, never vendor secrets in the SDK credential store. An unavailable selected account disables the provider so the engine cannot fall back to a machine login. A provider nobody bound keeps the engine's own auth only for an owner who may use the machine login; for any other owner every unbound catalog provider is disabled, and a turn naming one is refused before the engine is asked, because the engine runs inside the server process and reads vendor keys from its environment. A binding enables its provider explicitly, because the engine's automatic activation counts only integration connections and a binding leaves those empty; a provider the workspace policy disabled stays disabled. The engine resolves a bound provider's key through its integration's env connection ahead of the catalog's `apiKey`, so the binding empties that integration's env method through the engine's own integration hook; the process environment is never edited. The engine shares one provider catalog across sessions and serves one owner, whose accounts are chosen per person: a credential change rebinds the engine once and moves every open session to the new selection together, while a new session opened with a different selection than the live ones is refused. Catalog and integration transforms can be overwritten by config plugins, so bindings read back final rows, move their transform last when needed, and settle before acknowledging a change.

Engine reads annotate an SDK `ClientError` with operation and workspace because an undeclared non-2xx response otherwise carries little context. That error is matched structurally to keep the native SDK graph lazy. The launch document carries only the directory's shared MCP servers and skills. It is the folder's, not a session's: the engine configures MCP and skills per location, so a projection change applies to every session in the folder and the latest document wins; a session joining the folder writes its own document for the same reason. The transport lists the first-party MCP server with the calling session's credential and registers its tools through the SDK session tool port. Tool execution uses an in-process callback bound to that registration, so another engine session cannot borrow it. Conflicting tool definitions in a location fail rather than choosing one owner silently. Unregister reloads the location only after installation has settled.

Cancellation bounds the interrupt request and correlated terminal confirmation together with the caller's deadline and signal. Expiry reports the existing running/unknown outcome and releases the event subscription even when the SDK interrupt never settles. The focused cancellation tests inject that stalled SDK boundary because the real engine cannot deterministically produce it.
