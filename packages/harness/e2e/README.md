# Harness flows

Run `bun run build:packages` from the repository root, then `bun run --cwd packages/harness flows` for every flow, or `bun run --cwd packages/harness flows H0 H3b` for the named ones. `bun run --cwd packages/harness typecheck` checks this folder with its own `tsconfig.json`, and `bun run --cwd packages/harness test` runs the pin tests in `harness/`. `CLAXEDO_E2E_KEEP_DATA=1` keeps the temporary stack directory for diagnosis. Give concurrent runs disjoint `CLAXEDO_E2E_PORT_RANGE` values, such as `46200-46299`. The daemon runs on the Node range `packages/claxedo-local-server/package.json` declares in `engines.node`; a `node` on PATH outside it is refused, so set `CLAXEDO_E2E_NODE` to a supported binary.

Each flow starts the real local daemon and workspace runtime. It creates sessions and sends prompts through HTTP, reads live SSE frames, reads stored messages through HTTP, and checks a server readback. The scripted ACP process speaks ACP over stdio, and the scripted model server answers real model requests. These are the only scripted turn boundaries. Pi is installed at the runtime's pinned version when missing. Each stack has its own temporary data directory, isolated home and XDG directories, and a rejecting egress proxy. H0 requires its egress record to be empty.

Local stacks compose `startLocalServer` through `harness/local-daemon-entry.ts`. Hosted stacks run the certified Cloudflare Worker on Miniflare with local D1/R2, and their relay is the production `workspace-relay/wrangler.toml` Worker and `WorkspaceRelayRoom` Durable Object under workerd, in a separate Node process with its own home and storage directory. The boot map and the assertions with no hosted equivalent are in [harness/BOOT_TARGETS.md](harness/BOOT_TARGETS.md).

A Codex flow reaches an MCP tool the way a real model does: Codex defers MCP tools behind its `tool_search` tool, so the flow scripts a `tool_search` call (`format: "tool_search"`), the scripted model records the namespaces Codex returns in `tool_search_output`, and the flow then scripts a call to the loaded tool's `call` target.

A green flow shows the behavior in live frames, in stored messages, and in one independent server readback. A flow that proves a defect in the register is listed in `flows/expected-red.json` with its defect ids: it must fail, and the run fails when it passes, so its entry is removed in the change that proves the fix. Any other failing flow fails the run. A red run injects a fault at the boundary the flow claims to test, and must fail there. `CLAXEDO_E2E_RED=1` makes the scripted ACP agent and model endpoint reject every turn, which only proves H0 detects failed turns. A scripted endpoint can't prove live vendor behavior. Keep real harness programs pinned, and report unavailable programs or failing isolation as failures, never skips.

H19.default and H19.opencode boot the product sandbox entry (`host-entry.agent-plugins.ts`) with the driver's canonical boot environment. They check the default selection or lazy OpenCode composition, persisted session configuration/title and a live session update. H19.default's sandbox has no machine login, so a session is refused with `account_unavailable` until the owner's OpenAI account arrives in a signed config push, built by the control plane's delivery plan. The owner chose no default, so that push must keep the provisioned runner as the default. They do not send a provider turn; OpenCode provider credentials remain C-11. `CLAXEDO_E2E_CLOUD_FAULT=startup-key-withheld` removes the driver key before launch; `opencode-composition-refused` makes the lazy OpenCode store directory unwritable by placing a file there.

H33 changes the default harness of a running hosted sandbox, checks the sandbox reports it and still lists its transport commands, then runs an ACP cloud session, all without replacing the runtime.
