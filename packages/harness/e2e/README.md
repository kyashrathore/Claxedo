# Harness flows

Run `bun run build:packages` from the repository root, then `bun run --cwd packages/harness flows` for every flow, or `bun run --cwd packages/harness flows H0 H3b` for the named ones. `bun run --cwd packages/harness typecheck` checks this folder with its own `tsconfig.json`, and `bun run --cwd packages/harness test` runs the pin tests in `harness/`. `CLAXEDO_E2E_KEEP_DATA=1` keeps the temporary stack directory for diagnosis. Give concurrent runs disjoint `CLAXEDO_E2E_PORT_RANGE` values, such as `46200-46299`. The daemon runs on the Node range `packages/claxedo-server/package.json` declares in `engines.node`; a `node` on PATH outside it is refused, so set `CLAXEDO_E2E_NODE` to a supported binary.

Each flow starts the real local daemon and workspace runtime. It creates sessions and sends prompts through HTTP, reads live SSE frames, reads stored messages through HTTP, and checks a server readback. The scripted ACP process speaks ACP over stdio, and the scripted model server answers real model requests. These are the only scripted turn boundaries. Pi is installed at the runtime's pinned version when missing. Each stack has its own temporary data directory, isolated home and XDG directories, and a rejecting egress proxy. H0 requires its egress record to be empty.

A green flow shows the behavior in live frames, in stored messages, and in one independent server readback. A flow that proves a defect in the register is listed in `flows/expected-red.json` with its defect ids: it must fail, and the run fails when it passes, so its entry is removed in the change that proves the fix. Any other failing flow fails the run. A red run injects a fault at the boundary the flow claims to test, and must fail there. `CLAXEDO_E2E_RED=1` makes the scripted ACP agent and model endpoint reject every turn, which only proves H0 detects failed turns. A scripted endpoint can't prove live vendor behavior. Keep real harness programs pinned, and report unavailable programs or failing isolation as failures, never skips.
