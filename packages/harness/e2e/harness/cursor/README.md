# Scripted Cursor backend

`backend.ts` answers the Cursor SDK's Connect-RPC requests from named scripts. It uses the message and service descriptors bundled in the `@cursor/sdk` version `packages/harness/package.json` pins to decode requests and encode replies. The harness does not copy or maintain a protobuf schema.

The SDK exports its public agent API but not every descriptor the backend needs. `descriptors.ts` loads the pin's `dist/esm` build in an isolated temporary directory, exposes the SDK's internal module loader and the unexported server-config, bidi and analytics service descriptors there, and removes the directory when the backend closes. It reads their minified names from the build itself, and throws unless the installed version is the pin and each name, loader and module header occurs exactly once where it expects it, so a changed SDK layout fails instead of using guessed messages. `descriptors.test.ts` holds the credential broker's Cursor row to exactly the pin's agent, bidi, dashboard and server-config methods, so an SDK bump that adds a method fails there rather than as a refused request in a brokered session.

The flow stores a placeholder Cursor account through the product's credential routes and points the local provider configuration at this loopback backend. The daemon projects a workspace-specific broker binding into its runtime. The backend requires the exchanged access token on Connect calls, so H1.cursor verifies that the broker performs the exchange with the real key and substitutes the token without returning it to the SDK.
