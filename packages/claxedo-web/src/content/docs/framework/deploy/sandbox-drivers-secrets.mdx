`@claxedo/sandbox-manager` handles sandbox placement and lease management for
running `@claxedo/workspace-runtime` inside a provider sandbox. It owns the
generic pieces — `SandboxManager`, `SandboxLease`, `SandboxTarget`,
`SandboxLeaseStore`, `SandboxDriver` — plus provider drivers for Cloudflare,
Daytona, Docker, a fetch bridge, Modal, and Vercel.

<Note>
The package deliberately does **not** own product auth, billing, Convex schema,
SQLite app storage, routes, or relay tokens. Applications provide those through
adapters and call `createSandboxManager`.
</Note>

## Choosing a driver

Pick a driver by what your sandbox needs to do with credentials — see
[Credentials & the sandbox boundary](/framework/concepts/credentials-sandbox) for the full
model. The decisive property is `secretBrokering`: whether the driver can hand
the sandbox a credential it can **use** but never **read**.

| Driver | `secretBrokering` | Mechanism |
| --- | --- | --- |
| Daytona | `native` | `daytona.secret.create({name, value, hosts})`; the sandbox env holds an opaque `dtn_secret_…` placeholder and an egress proxy substitutes the real value only for allowlisted hosts. |
| Vercel | `native` | Firewall header-transform (`updateNetworkPolicy`): the value is spliced onto egress to allowlisted hosts as `header`; the sandbox makes an unauthenticated request. |
| Cloudflare | `proxy` | Worker-proxy pattern: the driver sends the value to the sandbox Worker (API-token-gated), which stores it in KV, mints a short-lived per-sandbox JWT, and sets `CLAXEDO_EGRESS_PROXY_URL` / `CLAXEDO_EGRESS_TOKEN` / `CLAXEDO_EGRESS_HOSTS` in the container. Brokered-host egress routes through the Worker, which injects the credential as `header`. |
| Modal | `none` | Modal Secrets are encrypted by-reference but exposed as **readable env vars** — cannot satisfy the never-readable contract. |
| Docker, fetch | `none` | Plaintext env only. |

## Provision a sandbox with a brokered secret

Set `env` for credentials the agent is meant to hold, and `secrets` for
credentials it must use but never read:

```ts
// `manager` is a SandboxManager from createSandboxManager({ leaseStore, driver })
// — your app supplies the lease store and provider driver.
const workspaceId = "ws_1"
const notionToken = process.env.NOTION_TOKEN! // the credential to broker

await manager.ensure(workspaceId, {
  homeRegion: "us-east",
  secrets: [{
    name: "NOTION_TOKEN",
    value: notionToken,          // never enters the sandbox in plaintext
    hosts: ["api.notion.com"],   // substituted/injected only for these hosts
    header: "Authorization",     // required for Vercel and the Cloudflare proxy driver; optional for Daytona
  }],
})
```

## Fail-closed behavior

A brokered secret is never silently downgraded to readable env. `native` and
`proxy` drivers keep the value out of the sandbox and provision normally. A
`none` driver refuses to provision rather than expose or drop the credential:

```text
status: "unavailable", error: "secret_brokering_unsupported"
```

Brokered secret values are never written to labels, never logged, and never
captured in a driver snapshot.

## Egress with the Cloudflare proxy driver

<Warning>
`native` brokering (Daytona, Vercel) is transparent — existing code reaches the
real host and the platform injects the credential. Cloudflare `proxy` is **not**
transparent: the sandbox must route brokered-host requests through
`CLAXEDO_EGRESS_PROXY_URL`, sending the `CLAXEDO_EGRESS_TOKEN` bearer and the
`x-claxedo-egress-target` header. The reusable core lives at
`@claxedo/sandbox-manager/drivers/cloudflare-egress` (mint/verify +
`handleEgressRequest`).
</Warning>

## Provider SDK conformance

The Daytona secret API and Vercel network-policy transform shapes follow the
providers' official docs and are validated structurally against the pinned SDK
types. Like all provider calls in the package, they are exercised against mocks
in unit tests, with live-SDK integration verified at deploy time.
