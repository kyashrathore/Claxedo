The hosted Claxedo control plane runs as a Cloudflare Worker. It is a **pure
control plane**: auth, workspace ownership, relay target resolution, token
minting, user-hosted registration/heartbeat/pause, JWKS, health, and device
login.

<Note>
Local execution — the embedded workspace runtime, PTY/process/file routes, the
tunnel, SQLite, and the sandbox supervisor — stays in the local Node server and
is **never** bundled into the Worker.
</Note>

The Worker entrypoint is `packages/claxedo-server/src/worker.ts`, which serves
the Worker-safe app from `src/hosted-app.ts`.

## Agent deploy

Copy this brief into a coding agent that has the repository checked out and
Cloudflare Wrangler access. The agent should stop for secrets and account-level
choices, explain each required value, and verify the deployed system before it
finishes.

```text
Deploy my Claxedo control plane to my Cloudflare account from this repository.

Follow packages/claxedo-docs/deploy/hosted-control-plane.mdx and the existing
packages/claxedo-server/wrangler.toml. First inspect the current configuration
and run the Worker import-graph tests plus a Wrangler dry run. Then list the
required public configuration and secrets, explain where each value comes from,
and ask me for only the values you cannot safely generate or discover. Never
print secret values after they are entered.

Deploy the Worker only after the preflight passes. Verify /api/claxedo/health,
/api/claxedo/mode, /.well-known/jwks.json, and compatibility metadata on the
deployed URL. Remember that the Cloudflare Worker is the control plane: confirm
the workspace authority, relay, and local or sandbox runtime are connected
rather than claiming that local execution runs inside the Worker. Finish with
the deployed URL, verification results, remaining optional integrations, and
the exact rollback command.
```

Cloudflare's repository deploy buttons are not used here yet because this is a
monorepo and the Worker depends on sibling workspace packages. The guided path
keeps the existing build graph intact while still handing the mechanical work
to an agent.

## Worker API surface

| Method | Path | Notes |
| --- | --- | --- |
| GET | `/api/claxedo/health` | `{"ok":true,"mode":"hosted-control-plane","localExecution":false}` on the Worker |
| GET | `/api/claxedo/mode` | status of configured deps (no secrets) |
| GET | `/api/claxedo/compatibility` | deployed component/protocol versions |
| GET | `/.well-known/jwks.json` | RAT signing public keys |
| POST | `/api/auth/device/code` · `/api/auth/device/token` | return `501 device_login_unconfigured` until a device-login issuer is configured |
| GET | `/api/workspace/:id/connection` | mints a Runtime Access Token (user-hosted) |
| POST | `/api/workspace/:id/connection/refresh` | re-mint with `previousJti` |
| POST | `/api/workspace/:id/user-hosted/challenge` | returns a signing challenge (CLI owns the host key) |
| POST | `/api/workspace/:id/user-hosted/register` | records the link, mints a Host Tunnel Token; does **not** start a tunnel |
| POST | `/api/workspace/:id/user-hosted/heartbeat` | client-signed; re-mints the Host Tunnel Token |
| POST | `/api/workspace/:id/user-hosted/pause` | pauses the link |
| ALL | `/api/workgraph` · `/api/workgraph/*` | forwards to the embedded `@claxedo/workgraph` HTTP router; tenant is derived from auth, no selector in the request |
| GET | `/internal/relay/target` · `/internal/relay/revocation` | resolver-token / loopback gated |
| POST | `/internal/sandbox-manager/gc` · `/internal/sandbox-manager/release` | manual sandbox GC / lease release; admin-token gated |
| POST | `/internal/workgraph/reconcile` | tenant-scoped WorkGraph reconciliation sweep; admin-token gated, rate-limited, accepts no owner/workspace/Stream/Task selector |

<Note>
The Worker also mounts an auth-gated shell-boot surface (`/api/claxedo/events`,
`/api/claxedo/bootstrap`, `/global/health`, `/global/config`, `/project`,
`/path`, `/provider`) and signed control routes (`/api/control/sessions`,
`/api/control/*`). The complete surface is documented in
`packages/claxedo-server/src/hosted-app.ts`.
</Note>

<Note>
The host keypair is owned by the CLI / local runtime, not the server. Register
is a two-step, client-signed flow: `challenge` → the CLI signs the nonce with
its local private key → `register`. The control plane never holds a host private
key and never starts the tunnel — the CLI does, using the returned Host Tunnel
Token.
</Note>

## Configuration

Local development needs none of these — the local server boots on loopback
defaults. These are the Worker's production knobs, set as Worker secrets
(`wrangler secret put NAME`) unless noted.

### Required

| Name | Purpose |
| --- | --- |
| `CLAXEDO_SIGNED_CLOUD_AUTH` | `"1"` to enable signed auth (set as a `[vars]` value) |
| `CLERK_JWT_ISSUER`, `CLERK_JWKS_URL` | signed-auth verification (`CLERK_JWT_AUDIENCE` optional) |
| `CLAXEDO_WORKSPACE_AUTHORITY_URL` | hosted workspace/link/audit state |
| `CLAXEDO_WORKSPACE_RELAY_URL` | relay URL returned in connection data |
| `CLAXEDO_RELAY_RESOLVER_TOKEN` | authorizes `/internal/relay/*` callers |
| `CLAXEDO_RUNTIME_ACCESS_TOKEN_PRIVATE_KEY_PEM` | RAT/HTT signing key (EdDSA PKCS8) |

<Warning>
The Worker **fails closed** (`503`) at boot if signed auth, the workspace
authority URL, relay URL, resolver token, or the signing key is missing.
</Warning>

### Common

| Name | Purpose |
| --- | --- |
| `CLAXEDO_RUNTIME_ACCESS_TOKEN_PUBLIC_KEY_PEM` | published at JWKS |
| `CLAXEDO_CONTROL_PLANE_SERVICE_TOKEN` | unsigned relay-revocation queries to Convex |
| `CLAXEDO_RUNTIME_ADMIN_TOKEN` | authorizes both `/internal/sandbox-manager/*` (GC / lease release) and `/internal/workgraph/reconcile`; must differ from the resolver token |
| `CLAXEDO_SANDBOX_DRIVER` | sandbox driver selection — the Worker accepts `cloudflare`, `daytona`, or `fetch` (Node-only `modal`/`vercel`/`docker` are rejected); auto-detected from provider creds when unset |
| Cloudflare driver | `CLOUDFLARE_SANDBOX_API_TOKEN` + `CLOUDFLARE_SANDBOX_WORKER_URL` (primary); `CLOUDFLARE_API_TOKEN` is accepted only as a compatibility fallback for the token when `CLOUDFLARE_SANDBOX_API_TOKEN` is unset |
| Daytona driver | `DAYTONA_API_KEY` + `CLAXEDO_DAYTONA_SNAPSHOT` |
| fetch-bridge driver | `CLAXEDO_SANDBOX_DRIVER_URL` |
| `CLAXEDO_DEVICE_LOGIN_ISSUER` (+ optional `_CLIENT_ID`) | device-login broker; until set, the device endpoints return `501 device_login_unconfigured` |
| `CLAXEDO_POSTHOG_KEY`, `CLAXEDO_POSTHOG_HOST` | optional telemetry (fetch-based) |

Additional knobs — per-region relay endpoints, request rate-limit caps,
key-rotation `_NEXT_*` extras, and device-login URL/audience/scope overrides —
exist with sensible defaults; see the package source if you need them.

## Build and deploy

From `packages/claxedo-server`:

```sh
# Verify the bundle compiles and is local-free (no Cloudflare account needed)
npx wrangler deploy --dry-run --outdir dist-worker

# Deploy to staging (needs CLOUDFLARE_API_TOKEN + account)
npx wrangler secret put CLERK_JWT_ISSUER --env staging   # …repeat per secret
npx wrangler deploy --env staging
```

`nodejs_compat` is enabled as a small compatibility net and to populate
`process.env` from bindings. Control-plane signing and JWKS use **global Web
Crypto**, not `node:crypto`.

## Verify

```sh
BASE=https://claxedo-control-plane-staging.<your-subdomain>.workers.dev

# Unauthenticated smoke
curl -s "$BASE/api/claxedo/health"          # {"ok":true,"mode":"hosted-control-plane","localExecution":false}
curl -s "$BASE/api/claxedo/mode"            # configured-dependency flags
curl -s "$BASE/.well-known/jwks.json"       # {"keys":[…]}

# Signed smoke (TOKEN = a Clerk-issued user bearer Convex trusts)
curl -s -H "authorization: Bearer $TOKEN" "$BASE/api/workspace/<id>/connection"
```

## Guardrails

`src/worker.import-graph.test.ts` statically walks the Worker import graph and
fails if any local-only module (`workspace-store`, `workspace-supervisor`,
`embedded-workspace-runtime`, `user-hosted-tunnel`,
`credentials/store|registry|local`, `cloud/sandbox`, `server.ts`, …) or
Node-only package (`@hono/node-server`, `better-sqlite3`, `node-pty`,
`node:child_process`, `node:crypto`, `fs`, `posthog-node`, …) enters the graph.
Run it and the bundle dry-run before every Worker change.

## Known dependency: device login

<Warning>
Device login is not yet available. `/api/auth/device/code` and
`/api/auth/device/token` return `501 device_login_unconfigured` until a
device-login issuer is configured (`CLAXEDO_DEVICE_LOGIN_ISSUER`) and the
workspace authority trusts the CLI-login token issuer. A fully headless
`claxedo login → register` smoke test is therefore blocked until then; a
browser-issued Clerk bearer exercises the signed surface in the interim.
</Warning>
