A brokered secret is a credential the sandbox may **use** for outbound
requests but must **never read**. Drivers declare how they honor that
contract (`secretBrokering: "native" | "proxy" | "none"`), and the manager
fails closed: it refuses to provision at all rather than leak —
`{ status: "unavailable", error: "secret_brokering_unsupported" }`, not a
warning.

## Run

```bash
bun run recipe:07-sandbox-secrets
```

<Note>
Part 1 (the refusal) needs nothing — it is decided from driver metadata
before any docker command runs. Part 2 provisions a real docker sandbox only
when the claxedo sandbox image is already present locally (it is a multi-GB
pull, so the recipe never pulls it for you).
</Note>

## The core

```ts
const manager = createSandboxManager({
  leaseStore: createMemoryLeaseStore(),
  driver: createDockerSandboxDriver({ image, syncLocalAuth: false }), // secretBrokering: "none"
  appLabel: "claxedo-cookbook",
})

const refusal = await manager.ensure("cookbook-secrets-demo", {
  homeRegion: "local",
  secrets: [{
    name: "GITHUB_TOKEN",
    value: "ghp_this-value-must-never-enter-the-sandbox",
    hosts: ["api.github.com"],
    header: "authorization",
  }],
})
// refusal = { status: "unavailable", error: "secret_brokering_unsupported", … }
```

Full source: [`src/recipes/07-sandbox-secrets.ts`](https://github.com/kyashrathore/Claxedo/blob/dev/claxedo-cookbook/src/recipes/07-sandbox-secrets.ts)

## Lift this into your app

Pass credentials that must stay unreadable as `secrets` (name, value,
allowlisted `hosts`, and the `header` to inject) and let the manager decide:
on daytona/vercel the provider injects on egress natively, on cloudflare a
host-operated egress proxy does, and on anything declaring `"none"` you get a
refusal — which is the correct production behavior. The full model is in
[Credentials & the sandbox boundary](/framework/concepts/credentials-sandbox).
