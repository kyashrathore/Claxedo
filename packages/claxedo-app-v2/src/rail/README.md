# Rail

Owns: the main sidebar's content (`MainSidebar`), ported from today's app's rail: the global rows (Tasks, Marketplace, then any plugin's `sidebarItems`), the Projects tree with each project's sessions nested under it, today's account card in the footer (`AccountCard`) with a Usage button beside it (the owner's 21:10 rail foot: no separate Settings row; Settings is in the account menu and on ⌘,); and the workbench header's compact tabs (`CompactSwitcher`). The shell draws the rail's frame around it (`src/shell/view/sidebar.tsx`: the `rail-sidebar` nav, its header strip with Hide/Pin Sidebar, the resize grip).

## Concepts

- **Project sections** (`project-sections.ts`) come from `useProjectList()` (`src/projects`): today's sidebar project list, in its order. A section opens its project's draft at the project's folder placement (`server.placements`, matched by `projectId`, never by a folder path). A project with no placement in the catalog, or whose cloud workspace is not ready, is dimmed.
- **Rail rows** (`RailRow` in `model.ts`): a project's rows are ONE derived list, `railRows(terminals, sessions)`, a union of `terminal` and `session` rows keyed by kind and id, terminals first as today; `ProjectRows` renders it and picks `TerminalRow` or `SessionRow` by kind, so neither row knows the other. Terminals come from `useTerminals()` (`src/terminal`) for every placement of the project, retained while the project is listed; a click opens the terminal's pane, and its close ends the PTY. A project opens when it has terminals, as today.
- **Session rows** are a read-only projection of `useSessionStores().list`, grouped by `ref.projectId` (`rowsByProject`); archived rows and subagents never show (subagents are panel tabs). The session list store owns rows, order (`human_turn_desc`) and status; the rail never fetches, orders or patches them.
- **Paging**: a project shows 5 rows, and "Load more" shows 5 more, asking the store for its next page when the loaded rows run out. The store pages the whole list, so there is no per-project total.
- **Navigation status** (`model.ts`): `permission` (the session waits on you) and `error` draw a blue dot, `working` (also pending, retrying and recovering) a ring spinner, and `idle` nothing, in the glyph column before the title.
- **Age**: `createdAt` as a compact age ("<1m", "2h", "3d"), refreshed every 10 s by the app's one clock (`useClock()` from `src/lib/clock.tsx`), as today; the palette's session ages read the same clock.
- **Engagement** (`hover-engagement.ts`): a row's archive button and a project header's actions mount only while the pointer or keyboard is on them, so the accessibility tree holds one "New Session" button and one archive button at a time.
- **Compact tabs** (`CompactSwitcher`, `switcher-items.ts`): today's strip in the workbench header while the sidebar is unpinned. One tab per alive workbench content in insertion order (sessions, drafts, terminals, plugin panes; files are panel tabs), titled by its pane kind, with the project's outline avatar (or the ring spinner while working, a corner dot when it needs you), a hover card (title, project · workspace, status), a close button and middle-click close. A click shows that content at once; the active tab scrolls into view. Holding ⌘ for 500 ms shows each tab's `claxedo.surface.N` keybind when such a command is registered.
- **Account card** (`account-card.tsx`): today's card and menu over `useAuth()`. Signed in, it shows the avatar and name; while signing in, a spinner and "Signing in…"; otherwise "Sign in" when the server issues sessions (`capabilities.signedIn`) and the browser can sign in, else today's local "Not signed in" with the monitor mark. The menu holds Usage (Settings → Usage), Settings, Help, then Cancel sign in, Sign in or Log out; a failed sign-in or sign-out toasts. Today's organization switch is not ported: the adapter has no route for the user's organizations.
- **Opening a session** pushes today's URL: `/s/<id>` for a session on this machine's folders and worktrees, `/w/<ws>/session/<id>` for a cloud or another machine's workspace, so Back returns.
- **Row actions**: hover archive (no confirm; archiving the open session moves to its next sibling, else to the project's draft), and a context menu (right-click or double-click) with Rename, Archive and Delete. Their outcome reaches the row through the session list store's events.

## Flows

Flow 03 (a project's draft becomes the new session's row), flow 13 (a terminal's row closes it), flow 10 (order, status, rename, archive, delete), flow 31 (the rail's rows equal the server's list) and flow 33 (the drawer on a phone).
